# クイズ 2. アドレス、サブネット、インターフェイス

> **サポート対象バージョン**: Ubuntu Server 24.04 LTS（主環境）、Rocky Linux 9（代替環境）
> **最終更新日**: 2026年9月15日

[レッスンに戻る](../../../networking/beginner/02-addressing-interfaces.md) | [コースの準備](../../../networking/beginner/README.md)

分離された 2 台の VM を使うラボの前提に従ってください。解説を開く前に答えを選びます。以下の例は解釈用であり、ホストを再構成する指示ではありません。

1. クライアントがサーバー `192.0.2.20:8080` に HTTP リクエストを直接送信します。正しい説明はどれですか？

   - A) `8080` はサーバーの MAC アドレスである。
   - B) Ethernet はローカルリンク上で MAC アドレスを使用し、IP はルーティングされるエンドポイントを識別する。TCP ポート `8080` は、サービスがリッスンするトランスポートのエンドポイントを識別する。
   - C) サーバーに IP を割り当てると、自動的に HTTP が起動する。
   - D) TCP と UDP のポート `8080` は常に同じプログラムに到達する。

<details>
<summary>解答を表示</summary>

**解答: B**

**解説:** ローカル Ethernet フレームには IP パケットが入り、その中にトランスポート情報とアプリケーションデータが含まれます。ポートはプロトコルごとの番号であり、ケーブルではありません。アドレスを設定しただけではリスナーは作られません。ICMP echo が成功しても、TCP `8080` が開いているとは証明されません。

</details>

2. `192.0.2.10/24` のネットワークアドレス、ブロードキャストアドレス、通常のホスト範囲はどれですか？

   - A) ネットワーク `.10`、ブロードキャスト `.24`、ホスト `.1`～`.9`
   - B) ネットワーク `192.0.2.0`、ブロードキャスト `192.0.2.255`、ホスト `.1`～`.254`
   - C) ネットワーク `192.0.0.0`、ブロードキャスト `192.0.255.255`、ホスト `.0`～`.255`
   - D) このラボでは 256 個のアドレスすべてが通常のホストアドレスである。

<details>
<summary>解答を表示</summary>

**解答: B**

**解説:** `/24` はネットワークビットを 24 個使い、ホストビットを 8 個残すため、アドレス数は 256 個です。この通常のサブネットでは、ホストビットがすべて 0 または 1 のアドレスはそれぞれネットワークとブロードキャストを示し、ホストアドレスは 254 個です。`/31` と `/32` には特殊な用途があるため、同じ計算を当てはめないでください。

</details>

3. `192.0.2.70/26` と同じサブネットに属する宛先と、その理由はどれですか？

   - A) `.130`。最初の 3 オクテットが一致するため。
   - B) `.100`。`.64/26` の範囲は `.64`～`.127`、ホスト範囲は `.65`～`.126` だから。
   - C) `.20`。ドキュメント用アドレスならすべてローカルだから。
   - D) `.127`。サブネットのブロードキャストアドレスは推奨サーバーアドレスだから。

<details>
<summary>解答を表示</summary>

**解答: B**

**解説:** `/26` はホストビットを 6 個残すため、ブロックあたり 64 アドレスで、`.0`、`.64`、`.128`、`.192` から始まります。`.70` と `.100` は 2 番目のブロック、`.130` は 3 番目のブロックです。すべてのネットワークが `/24` だと決めつけず、実際のプレフィックスを比較してください。

</details>

4. クライアントには管理用デフォルトルートがあり、ラボ NIC には接続済みの `192.0.2.0/24` 経路があります。`.20` 宛てのパケットはどこへ向かいますか？

   - A) デフォルトルートは常に優先されるため、管理用経路を通る。
   - B) `/24` は `/0` より一致するプレフィックスが長いため、ラボ NIC から直接送信される。
   - C) `.1` は自動的にゲートウェイになるため、`.1` を通る。
   - D) ラボ NIC に DNS を設定するまで、どこにも送信されない。

<details>
<summary>解答を表示</summary>

**解答: B**

**解説:** 接続済みの経路の方が、より具体的です。同じサブネット内の IP アドレスを直接指定する通信に、ラボ用のゲートウェイや DNS は必要ありません。既存の管理用デフォルトルートを維持してください。ゲートウェイは実際に存在し、到達可能でなければなりません。末尾が `.1` のアドレスが自動的にルーターになるわけではありません。

</details>

5. 各機能の役割を正しく説明しているものはどれですか？

   - A) DHCP はすべてのパケットを転送し、DNS はクライアントの MAC を割り当て、ARP は名前を解決する。
   - B) DHCP はアドレス／構成をリースできる。DNS は名前レコードの問い合わせに応答し、ARP はリンク上の IPv4 次ホップ隣接ノードを MAC アドレスに解決する。
   - C) DNS が成功すれば、すべてのサービスに到達可能だと証明できる。
   - D) ARP はインターネット越しにある任意のサーバーの MAC アドレスを検出する。

<details>
<summary>解答を表示</summary>

**解答: B**

**解説:** ルーター経由でリモート IPv4 宛先に接続する場合、ARP が通常解決するのはリモートサーバーではなく、ローカルリンク上にあるルーターの MAC アドレスです。DHCP は構成情報の交換、DNS は名前解決を行います。これらは別々の問いに答えるため、それぞれ独立して成功または失敗します。

</details>

6. アドレスを追加する前に、どの証拠を使えばラボ NIC を確実に特定できますか？

   - A) 常に `eth1` である。
   - B) `ip a` の一覧で loopback を除いて 2 番目に表示される行である。
   - C) 完全な MAC アドレスが、ハイパーバイザーの記録にある内部ネットワーク接続用 NIC と一致する。
   - D) すでにデフォルトルートが設定されている。

<details>
<summary>解答を表示</summary>

**解答: C**

**解説:** ゲスト内の名前や一覧の順序は異なる場合があります。各 VM の管理用とラボ用の MAC アドレスを個別に記録し、`ip -br link` の表示と照合してください。デフォルトルートは管理経路を示す場合が多いため、変更しないでください。この演習でアドレスを追加する前に、ラボ NIC に既存の IPv4 アドレスがないという前提も満たす必要があります。

</details>

7. `ip a` は何を行いますか？ また、`UP` でも `LOWER_UP` ではない状態は何を意味することがありますか？

   - A) `ip a` はアドレスを追加し、`UP` ならインターネットアクセスが証明される。
   - B) `ip a` はアドレスを一覧表示する。管理上は有効なリンクでも、下位層のキャリアがない場合がある。
   - C) どちらの表示も DNS が動作することを意味する。
   - D) loopback の `UNKNOWN` は、ゲストが壊れていることを常に意味する。

<details>
<summary>解答を表示</summary>

**解答: B**

**解説:** `a` は address オブジェクトの略です。追加するには `add` 操作が必要です。管理上の有効化、キャリア、アドレス割り当て、ルーティング、サービス到達性は、それぞれ別に観測します。キャリアがない場合は IP 設定を変更する前に、仮想ケーブルとネットワーク接続を調べてください。

</details>

8. `ip -4 route get 192.0.2.20` は送信元 `.10` のラボ NIC を選びましたが、ping に応答がありません。この経路検索で何が証明されましたか？

   - A) 相手がパケットを受信した。
   - B) カーネルがその経路／送信元を選択すること。検索では probe パケットは送信されていない。
   - C) ファイアウォールが ICMP と TCP を許可する。
   - D) ARP による相手の解決が必ず完了している。

<details>
<summary>解答を表示</summary>

**解答: B**

**解説:** 経路選択はローカルの証拠です。ping を上限付きで実行した後に隣接ノードを調べ、ローカルリンクでの解決が未完了なのか、MAC は解決したが ICMP がフィルターされた可能性がある経路なのかを区別してください。経路決定をエンドツーエンドの成功とみなしたり、症状を隠すためにファイアウォールを無効にしたりしないでください。

</details>

9. 通信後、隣接ノードのエントリーに期待する相手の MAC アドレスが表示され、状態は `STALE` でした。これは何を意味しますか？

   - A) インターフェイスは永久に利用できない。
   - B) 対応関係がキャッシュされており、再利用時に再確認が必要になる状態である。直ちに失敗したことを意味しない。
   - C) 相手が必ず MAC を偽装した。
   - D) 隣接ノードのエントリーをすべて flush しなければならない。

<details>
<summary>解答を表示</summary>

**解答: B**

**解説:** 隣接ノードの状態は到達可能性の確認に応じて変化します。`REACHABLE` は最近確認済み、`INCOMPLETE` は解決中、`FAILED` は解決に失敗した状態です。通信前にテーブルが空でも正常な場合があります。すべてのキャッシュ済みエントリーが常に `REACHABLE` と表示されることを求めず、MAC アドレスを記録と照合し、実際の通信結果を使ってください。

</details>

10. 手動で追加したアドレスに `valid_lft forever` と表示されます。再起動後も残りますか？ また、クリーンアップでは何を削除すべきですか？

   - A) 残る。ゲストのアドレステーブル全体を削除する。
   - B) 永続化は示されない。特定したラボ NIC から、正常に追加した正確な IP／プレフィックスだけを削除し、その NIC が元々 down だった場合に限り、down 状態へ戻す。
   - C) 残る。削除するには Linux の再インストールしかない。
   - D) 先に管理用デフォルトルートを削除する。

<details>
<summary>解答を表示</summary>

**解答: B**

**解説:** `forever` は実行時の有効期限タイマーがないという意味であり、設定ファイルに保存されたことを意味しません。このレッスンでは、IPv4 アドレスが元々ないという前提のため、唯一のラボ用 IPv4 アドレスを削除すれば、自動作成された接続済み経路も削除されます。再起動またはネットワーク管理サービスによってすでにアドレスが消えている場合は、不在を確認して削除を省略してください。推測で復元せず、記録した変数と元の状態に従って復旧します。

</details>

11. ラボ NIC に `fe80:` で始まる IPv6 アドレスが表示されました。どのように対応するのが適切ですか？

   - A) IPv4 が動作するよう、IPv6 を全体的に無効にする。
   - B) リンクローカルである可能性が高いと判断し、既存の IPv6 設定を変更せず、IPv4 の演習を続ける。
   - C) IPv6 アドレスはすべてグローバルなので、インターネットに到達できるとみなす。
   - D) そのアドレスに対する IPv4 ARP エントリーを設定する。

<details>
<summary>解答を表示</summary>

**解答: B**

**解説:** IPv6 アドレスは 128 ビットです。リンクローカルの範囲はそのリンク内に限られ、宛先として使うときにインターフェイスの zone が必要な場合があります。IPv6 は ARP ではなく Neighbor Discovery を使い、IPv4 形式のブロードキャストはありません。リンクローカルアドレスがあるだけではインターネットへの到達性は証明されません。

</details>

12. 適切で完全な完了報告はどれですか？

   - A) 「コマンドを読んだので、例を実環境でテストした。」
   - B) 「ラボのアドレスがあるので、すべての TCP サービスが動作する。」
   - C) 「2 つのラボ NIC を MAC アドレスで確認し、アドレス／経路と範囲を限定した到達性の証拠を検証し、管理用の設定を保持した。その後、自分のアドレスだけを削除し、記録したリンク状態を復元した。」
   - D) 「host-only ネットワークは常に分離されており、DHCP が有効になることはない。」

<details>
<summary>解答を表示</summary>

**解答: C**

**解説:** 完了の前提には構成、証拠、復旧が含まれます。内部専用ネットワークのラボには DHCP／アップリンクがありません。host-only の既定設定も同じだと決めつけないでください。レッスン内の例は説明用であり、実環境でのテスト記録ではありません。次のレッスンでは、残存する変数に依存せず永続構成を設定します。

</details>
