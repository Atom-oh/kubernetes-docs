# 総合演習: コンテナとクラウドのクイズ

全 6 問です。各回答を自分の言葉で説明してください。

1. IP アドレスへのリクエストは HTTP 200 を返しますが、getent はサービス名を解決できません。最初に何を調べますか？

   - A) CPU の輻輳制御アルゴリズム
   - B) 名前解決経路
   - C) HTTP のファイル権限だけ
   - D) あらゆる CNI の実装

<details>
<summary>回答を表示</summary>

**回答: B) 名前解決経路**

**解説:** IP 接続とアプリケーションの応答は確認できているため、名前の解決方法を調べてください。特定の DNS サーバーを原因とするには、さらに証拠が必要です。

</details>

2. サーバーが HTTP 404 を返しました。このリクエストから何が分かりますか？

   - A) すべてのポートが開いている
   - B) ルーティングテーブルが空である
   - C) サーバーとの間で HTTP 応答が交換された
   - D) インターネット全体が正常である

<details>
<summary>回答を表示</summary>

**回答: C) サーバーとの間で HTTP 応答が交換された**

**解説:** 404 は HTTP レイヤーの応答です。パスとサーバーログを比較してください。ファイアウォール全体をリセットする根拠にはなりません。

</details>

3. ss には 127.0.0.1:8000 のリスナーだけが表示され、サーバー自身からのリクエストは成功しました。リモートからの失敗を調べるうえで中心となる確認事項は何ですか？

   - A) リスナーがリモートリクエストの宛先アドレスにバインドしているか確認する
   - B) クライアントの localhost とサーバーの localhost は同じものだと仮定する
   - C) DNS TTL を常に増やす
   - D) SELinux を無効にする

<details>
<summary>回答を表示</summary>

**回答: A) リスナーがリモートリクエストの宛先アドレスにバインドしているか確認する**

**解説:** ループバックはそのネットワーク名前空間に属します。サーバーのラボ IP でトラフィックを受信するには、適切にバインドされたリスナーと適切なアクセスルールが必要です。

</details>

4. UFW の独立した TCP 8000 許可ルールだけを削除しました。新しい鍵のみの SSH 接続は引き続き成功しますが、HTTP は失敗します。意図したポリシーを維持する復旧方法はどれですか？

   - A) 残っているラボ用拒否ルールの後に HTTP 許可を追加する
   - B) ラボ用拒否ルールと SSH ルールをすべて削除する
   - C) UFW を無効にし、以前の SSH セッションがあることを復旧の証拠とする
   - D) 元のスコープ付き HTTP 許可を拒否ルールより前に挿入し、ルールの順序、HTTP 200、新しい鍵のみの SSH 接続を確認する

<details>
<summary>回答を表示</summary>

**回答: D) 元のスコープ付き HTTP 許可を拒否ルールより前に挿入し、ルールの順序、HTTP 200、新しい鍵のみの SSH 接続を確認する**

**解説:** SSH と HTTP にはそれぞれ別の許可ルールがあるため、HTTP の障害では TCP 22 とデフォルトポリシーを変更しないでください。UFW では配置が重要です。一致する拒否ルールの後ろに追加した許可は効果がありません。多重化していない新しい鍵ログインを障害の前、最中、後にテストし、ロック解除済みのエージェントを前提とせず、暗号化された鍵のパスフレーズ入力を許可してください。firewalld の場合は、ランタイムの HTTP だけを削除/復元し、永続ルールが残っていることを確認します。削除後も HTTP が失敗しない場合は、遮断されたと断定せず、ほかの許可ルールとゾーンの動作を調査してください。

</details>

5. curl --resolve lesson.test:8000:192.0.2.20 は何を変更しますか？

   - A) すべての VM の DNS サーバー
   - B) この curl の実行に限ったホスト/ポートの対応付け
   - C) 永続的な /etc/hosts ファイル
   - D) Kubernetes Service の IP

<details>
<summary>回答を表示</summary>

**回答: B) この curl の実行に限ったホスト/ポートの対応付け**

**解説:** この上書きは今回の実行だけに適用されます。システムリゾルバーや、ほかのプログラムが使う対応付けは編集しません。

</details>

6. VM での演習から CNI に移るときも、どの原則を維持すべきですか？

   - A) Docker bridge とすべての CNI は同じ実装である
   - B) Service IP と localhost は同一である
   - C) 名前空間、アドレス、経路、ポリシー、観測ポイントを改めて特定する
   - D) 小さな HTTP リクエストでクラウドの最大スループットを証明できる

<details>
<summary>回答を表示</summary>

**回答: C) 名前空間、アドレス、経路、ポリシー、観測ポイントを改めて特定する**

**解説:** 診断上の問いは引き継げますが、実装と境界は異なります。クラスターの抽象化と実際のパケット経路を区別してください。

</details>
