# Calico ネットワーキングモードクイズ

> **関連ドキュメント**: [Calico Networking Modes](../../../networking/calico/03-networking-modes.md)
> **最終更新日**: 2026年9月12日

## クイズ

1. 外側がオプションなしの IPv4 ヘッダーである Calico IPIP では、ヘッダーのオーバーヘッドは何バイト追加されますか？
   - A) 8 バイト
   - B) 20 バイト
   - C) 50 バイト
   - D) 100 バイト

<details>
<summary>回答を表示</summary>

**回答: B) 20 バイト**

**解説:**
オプションがない場合、追加される IPv4 ヘッダーは 20 バイトです。Calico IPIP は IPv4 のみをサポートします。ヘッダーが小さいほどペイロードに使える領域は増えますが、それだけであらゆる NIC、カーネル、ワークロードにおける低レイテンシーや高スループットが証明されるわけではありません。

</details>

2. 外側が IPv4 の VXLAN で、内側に VLAN タグが追加されていない場合、Pod IP パケットに何バイトのオーバーヘッドが加わりますか？
   - A) 20 バイト
   - B) 30 バイト
   - C) 50 バイト
   - D) 64 バイト

<details>
<summary>回答を表示</summary>

**回答: C) 50 バイト**

**解説:**
50 バイトの内訳は、外側の IPv4 が 20、UDP が 8、VXLAN が 8、内側の Ethernet が 14 バイトです。外側の Ethernet ヘッダーはアンダーレイの IP MTU の対象外です。外側が IPv6 の場合、オーバーヘッドは 70 バイトになります。また、内側のトランスポートヘッダーのサイズは TCP と UDP で異なります。

</details>

3. Calico の CrossSubnet モードはどのように動作しますか？
   - A) 常にカプセル化を使用する
   - B) カプセル化を使用しない
   - C) サブネットをまたぐトラフィックだけカプセル化する
   - D) 同一サブネット内のトラフィックだけカプセル化する

<details>
<summary>回答を表示</summary>

**回答: C) サブネットをまたぐトラフィックだけカプセル化する**

**解説:**
CrossSubnet は、該当するノードアドレスと設定済みのサブネットマスクを比較します。同一サブネット内のノード間通信ではカプセル化を省略でき、異なるノードサブネット間の通信では、選択された IPIP または VXLAN のカプセル化を使用します。これは AZ やリージョンを検出する機能でも、サイト間接続を作成するサービスでもありません。

</details>

4. Direct（カプセル化しない）ルーティングモードの要件は何ですか？
   - A) 特殊なハードウェア NIC
   - B) 基盤ネットワークが Pod CIDR のトラフィックをルーティングできること
   - C) カーネルバージョン 5.0 以降
   - D) eBPF モードが有効であること

<details>
<summary>回答を表示</summary>

**回答: B) 基盤ネットワークが Pod CIDR のトラフィックをルーティングできること**

**解説:**
アンダーレイと戻り経路の両方で Pod アドレスをルーティングできる必要があります。BGP は方法の一つですが、静的ルートや、サポートされる Felix のクラスター内ルート設定も使えます。Calico 3.32 の Operator では clusterRoutingMode で、VXLAN 以外のクラスター内ルートを Felix に設定させることができます。外部への BGP 広告には、引き続き BGP が必要です。

</details>

5. IPIP と VXLAN のパフォーマンスについて、根拠をもって言えるのはどれですか？
   - A) VXLAN は常に高速である
   - B) 実際の NIC とオフロード、カーネルとデータプレーン、パケットサイズ、ルート、ワークロードによって異なる
   - C) 両者のパフォーマンスは同一である
   - D) パフォーマンスは Kubernetes のバージョンだけで決まる

<details>
<summary>回答を表示</summary>

**回答: B) 実際の NIC とオフロード、カーネルとデータプレーン、パケットサイズ、ルート、ワークロードによって異なる**

**解説:**
IPIP は IPv4 カプセル化ヘッダーが小さい一方、オフロード機能や実装の詳細もパフォーマンスに影響します。常に速いモードはありません。以前の二言語のベンチマーク記録は結果が一致せず、出典情報も不十分なため、パフォーマンスの保証ではなく報告例として扱います。

</details>

6. IPPool の ipipMode に設定できる値はどれですか？
   - A) On、Off
   - B) True、False
   - C) Always、CrossSubnet、Never
   - D) Enabled、Disabled、Auto

<details>
<summary>回答を表示</summary>

**回答: C) Always、CrossSubnet、Never**

**解説:**
ipipMode と vxlanMode には、Always、CrossSubnet、Never を設定できます。Always は対象となるノード間トラフィックに関する設定であり、同一ノード内の物理トンネルを意味しません。Operator の IPPool で使う別のカプセル化フィールドには、IPIPCrossSubnet や VXLANCrossSubnet などの値があります。この 2 つの API を混同しないでください。

</details>

7. IPPool の natOutgoing 設定は何を制御しますか？
   - A) Pod が受信 NAT トラフィックを受け取れるかどうか
   - B) このプールから Calico のすべての IPPool 外の宛先へ向かう対象トラフィックを送信元 NAT するかどうか
   - C) Pod 間で NAT を適用するかどうか
   - D) ノードが外部 Service に対して NAT を実行するかどうか

<details>
<summary>回答を表示</summary>

**回答: B) このプールから Calico のすべての IPPool 外の宛先へ向かう対象トラフィックを送信元 NAT するかどうか**

**解説:**
通常の判定条件は宛先が Calico のすべての IPPool の外にあることであり、単にクラスターの外という意味ではありません。設定が無効なプールでも、NAT を除外する宛先範囲を定義できます。また、Felix の追加除外設定にホスト IP を含めることもできます。NAT は通信を許可するものではなく、外部からの戻り経路を保証するものでもありません。

</details>

8. Calico の VXLAN がデフォルトで使用する UDP ポートは何番ですか？
   - A) 4789
   - B) 8472
   - C) 8080
   - D) 5473

<details>
<summary>回答を表示</summary>

**回答: A) 4789**

**解説:**
Calico のデフォルトは UDP 4789 で、変更も可能です。現在も VXLAN の実装によっては 8472 を使用します。これは古いポートに限られるわけではありません。IPIP は IP プロトコル 4 を使用するため、TCP/UDP のポート番号はありません。

</details>

9. Azure で Calico が管理するネットワークに IPIP ではなく適切な VXLAN 構成を選ぶのはなぜですか？
   - A) Azure が VXLAN のハードウェアアクセラレーションを提供するため
   - B) Calico のオーバーレイガイドでは、VXLAN はサポートされ、IPIP はサポートされない環境として Azure を挙げているため
   - C) Azure のポリシーで VXLAN が必須のため
   - D) Azure が VXLAN を自動設定するため

<details>
<summary>回答を表示</summary>

**回答: B) Calico のオーバーレイガイドでは、VXLAN はサポートされ、IPIP はサポートされない環境として Azure を挙げているため**

**解説:**
これは Calico ネットワーキングのサポート範囲に関する説明であり、すべての AKS デプロイに Calico オーバーレイを導入すべきだという意味ではありません。実際のプロバイダー CNI とポリシー統合を選んでください。UDR を追加しても、サポート対象外の IPIP カプセル化構成がサポートされるようにはなりません。

</details>

10. アンダーレイの実際の IP MTU が 1500 バイトで、外側が IPv4、ほかにカプセル化がない場合、VXLAN で使用できる Pod IP MTU はいくつですか？
    - A) Pod MTU を 1500 に設定する
    - B) 1450 バイト（1500 から 50 を差し引く）
    - C) 自動検出でカプセル化のオーバーヘッドがなくなるため 1500
    - D) Pod MTU を 1400 に設定する

<details>
<summary>回答を表示</summary>

**回答: B) 1450 バイト（1500 から 50 を差し引く）**

**解説:**
この条件では、IPv4 VXLAN のオーバーヘッドが 50 バイトなので、Pod IP パケットに使える MTU は 1450 バイトです。外側が IPv6 の場合、暗号化を使用する場合、物理経路の MTU が小さい場合、または eBPF の Service 経路を通る場合は、予算が変わることがあります。MTU の自動検出を使う場合も、実際のモードと経路が反映されていることを確認してください。

</details>

11. IPIP モードが有効なノードに作成されるインターフェースはどれですか？
    - A) vxlan.calico
    - B) tunl0
    - C) cali0
    - D) ipip0

<details>
<summary>回答を表示</summary>

**回答: B) tunl0**

**解説:**
この構成で通常使われる Linux の IPIP トンネルインターフェースは tunl0 です。これは IPIP が有効かつサポートされる環境でのみ関係します。暗号化を提供するものではなく、すべての Calico ネットワーキングモードで使われるインターフェースでもありません。

</details>

12. Calico IPPool を使ってアドレスを移行するとき、適切な進め方はどれですか？
    - A) IPPool の設定を直接変更する
    - B) 互換性があり重複しないプールを確認し、新規割り当てを制御して、ワークロードと依存関係を移行し、確認後に古いプールを廃止する
    - C) すべてのノードを同時に再起動する
    - D) 移行はサポートされていないため、クラスターを再構築する

<details>
<summary>回答を表示</summary>

**回答: B) 互換性があり重複しないプールを確認し、新規割り当てを制御して、ワークロードと依存関係を移行し、確認後に古いプールを廃止する**

**解説:**
CIDR/IPPool の移行は、カプセル化だけを変更する作業とは異なります。プールの所有者、クラスター CIDR との互換性、MTU、旧プールを明示的に指定した要求、残存する割り当て、アプリケーションのロールアウトを計画してください。Operator の nodeSelector に !all を指定しても、明示的に要求されたプールは除外されません。置き換えた Pod に新しいアドレスが付いたというだけでプールを削除しないでください。トンネルなどの割り当てや NAT、ルーティングへの影響が残っていることがあります。

</details>
