# Part 9: Kafka ベンチマーク検証クイズ

報告された測定値、因果関係の主張、再現性の確認を区別します。

## 1. RF3 のブローカー3台ではどのようなストレージ構成になり、F1 の 134.74 MiB/s はどう解釈すべきですか？

<details>
<summary>回答を表示</summary>

各ブローカーがすべてのパーティションのコピーを1つずつ保持します。エンコード後のログ速度とクライアントのペイロード速度は異なります。F1 は単一実行の短時間のクライアント報告値です。検証済みの持続的な 130～135 MiB/s の上限と主張する前に、キャッシュ、writeback、測定時間枠、単位を照合してください。

</details>

## 2. IOPS が低くバイトレートが高い場合、ボリュームのスループットだけがボトルネックだと証明できますか？

<details>
<summary>回答を表示</summary>

いいえ。シーケンシャル I/O やスループットの圧力とは整合しますが、インスタンスの EBS ベースライン/バースト、キャッシュ、クライアント、サンプリングの不確実性も関係します。ピーク値 135 をプロビジョニング済みの 125 MiB/s と同一視しないでください。制御した変更で仮説を検証します。

</details>

## 3. B1/B2 の p50 が 3 ms、p99 が 126/17 ms の場合、acks はテールレイテンシーだけに影響すると結論できますか？

<details>
<summary>回答を表示</summary>

いいえ。p99 の比率は約 7.412 ですが、平均値も 5.27/2.58 ms と異なります。整数ミリ秒でサンプリングした中央値が同じでも、基礎となるレイテンシーが同じとは証明できず、この1組の結果を一般化することもできません。acks=0 の callback はブローカーの永続化確認ではありません。

</details>

## 4. F4/F1 の 337.81/134.74 = 2.507 という比率が、レプリケーションコストだけの測定ではないのはなぜですか？

<details>
<summary>回答を表示</summary>

RF と acks がどちらも RF3/acks=all から RF1/acks=1 に変わっており、省略時の idempotence のデフォルトも異なります。実行時間、ブローカーあたりのデータ量、キャッシュ、クライアント側の制約も異なります。観測された比率はそのまま記録し、RF 単独の効果として示さないでください。

</details>

## 5. batch size、linger、record 数がすべて変わる場合、F6 をどのように説明すべきですか？

<details>
<summary>回答を表示</summary>

148.38 MiB/s は 134.74 MiB/s より 10.12% 高く、報告された CPU 範囲は低くなっています。CPU 中央値の差 39.19% は算術上の差であり、batch size だけの効果ではありません。ばらつきを反復測定していないため、スループットの差をノイズとは判定できません。

</details>

## 6. パディングした JSON の圧縮率と codec の順位を、ほかのログにもそのまま適用できますか？

<details>
<summary>回答を表示</summary>

いいえ。約63.2%が x のパディングであり、分布が特殊です。圧縮率も順位も普遍的な上限やランキングではありません。別の実装で AWK を再生成すると、ハッシュと圧縮率が変わる可能性があります。元のペイロード、イメージ、ツールのバージョンを保持してください。

</details>

## 7. E4 の低下と EC2 のネットワークカウンターを評価する際、どの交絡要因が重要ですか？

<details>
<summary>回答を表示</summary>

producer のスループットは 103.36 MiB/s から 57.37 MiB/s へ 44.49% 低下しますが、producer は consumer と 1.9 CPU のクライアント/NIC を共有しています。ブローカー CPU が低くても、クライアントの競合は否定できません。EC2 の rx/tx credit は別々です。F1 の rx は 136 MiB/s（約1.141 Gbps）、tx は 108 MiB/s（約0.906 Gbps）で、いずれも 1.25 Gbps を下回ります。両者を足してバーストを主張しないでください。

</details>

## 8. 新しい再現実験で、単位、定常状態、正常な配信をどのように検証すべきですか？

<details>
<summary>回答を表示</summary>

30M × 1024 B は 28.610 GiB です。普遍的に適用できる 10 GiB/1分の定常状態しきい値はありません。ウォームアップ、長い測定時間枠、drain、反復、共通の分母、実際のデバイスとタイムスタンプを記録してください。現行オプション、新しくデータを投入したトピック、最終的に成功した producer の件数と stderr、消費された内容を確認します。callback の失敗は終了ステータスだけでは検出できない場合があります。コスト見積もりは請求額ではありません。

</details>
