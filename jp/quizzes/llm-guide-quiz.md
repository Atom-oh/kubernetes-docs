# LLM で読む: llms.txt クイズ

1. このガイドブックの `llms.txt` ファイルには何が含まれ、何のために使いますか？
   - A) 韓国語の全コンテンツを Markdown 形式で格納しており、コンテキストウィンドウに全文を貼り付けるため
   - B) 各コンテンツページのタイトル、要約、生の Markdown URL のインデックスであり、LLM が必要なページだけを選んで取得できるようにするため
   - C) 自動採点用のクイズ解答集
   - D) スライド作成用のダイアグラム PNG 一式
<details>
<summary>解答を表示</summary>

**解答: B) 各コンテンツページのタイトル、要約、生の Markdown URL のインデックスであり、LLM が必要なページだけを選んで取得できるようにするため**

**解説:**
エンドポイントの表によると、`llms.txt` は各コンテンツページのグループ、タイトル、要約、生の Markdown URL を示すインデックスで、LLM が必要なページだけを選んで取得できるようにします。各コンテンツへのリンクは `/llms/<locale>/<source path>.md` を使うため、モデルはレンダリング済みページのサイドバーやスクリプトを含まないドキュメントソースを読み取ります。Markdown 全文は、別の `llms-full-ko.txt` / `llms-full-en.txt` ファイルに格納されています。クイズとラボはページごとには掲載されません。`## Optional` には、各言語のクイズインデックスとラボインデックスへのリンクが 1 つずつ含まれます。

</details>

2. 全文ファイルはどの言語で公開されていますか？
   - A) 韓国語のみ（`llms-full-ko.txt`）
   - B) 韓国語と英語の 2 ファイル（`llms-full-ko.txt`、`llms-full-en.txt`）
   - C) 韓国語、英語、中国語、日本語、スペイン語の 5 言語
   - D) すべての言語をまとめた単一の `llms-full.txt`
<details>
<summary>解答を表示</summary>

**解答: B) 韓国語と英語の 2 ファイル（`llms-full-ko.txt`、`llms-full-en.txt`）**

**解説:**
言語別の全文ファイルは `llms-full-ko.txt` と `llms-full-en.txt` です。インデックス、マニフェスト、セクション別のバンドル、ドキュメントごとの Markdown は、`https://www.atomai.click/kubernetes-docs/` 以下で提供される追加のエンドポイントです。韓国語版は「書籍全体のコンテキストまたは RAG のインデックス作成」に、英語版は「英語のツールやパイプライン」に推奨されています。

</details>

3. サイトのデプロイが成功したとき、`llms.txt` と全文ファイルはどのように生成されますか？
   - A) 編集のたびに作成者が 3 ファイルを手動で再アップロードする
   - B) 週次のニュースダイジェストワークフローが更新する
   - C) サイトのビルドで同じソースから生成され、一緒にデプロイされる
   - D) サーバーが LLM リクエストごとにオンデマンドでドキュメントを変換する
<details>
<summary>解答を表示</summary>

**解答: C) サイトのビルドで同じソースから生成され、一緒にデプロイされる**

**解説:**
ページには「サイトのビルドが同じソースからファイルを生成し、一緒にデプロイするため、公開済みのコンテンツと常に一致する」と記載されています。これらはデプロイパイプラインのビルド出力であり、手動アップロードでもオンデマンド変換でもありません。

</details>

4. `llms.txt` と全文ファイルでは、クイズドキュメントはどのように扱われますか？
   - A) すべてのクイズページが解答を含めてインデックスと全文ファイルの両方に掲載される
   - B) `llms.txt` の `## Optional` に言語ごとに 1 つあるクイズインデックスへのリンクだけが掲載される。個々のクイズページとその解答は、インデックスと全文ファイルのどちらにも含まれない
   - C) 個々のクイズページはすべてインデックスに載るが、全文ファイルからは除かれる
   - D) クイズページは全文ファイルに含まれるが、インデックスには載らない
<details>
<summary>解答を表示</summary>

**解答: B) `llms.txt` の `## Optional` に言語ごとに 1 つあるクイズインデックスへのリンクだけが掲載される。個々のクイズページとその解答は、インデックスと全文ファイルのどちらにも含まれない**

**解説:**
ページには、「クイズは `llms.txt` の `## Optional` に、クイズインデックスページへのリンクとしてのみ（各言語につき 1 つ）掲載されます。個々のクイズページ（解答を含む）はインデックスと全文ファイルのどちらからも除外されます。解答は LLM のコンテキストに含めるものではありません」とあります。そのため、LLM はクイズがあることや各言語のクイズインデックスの場所を確認できますが、個々のクイズページやその解答がフラットなインデックスや書籍全体のファイルに含まれることはありません。ラボガイドも `llms.txt` ではインデックスへのリンクだけが示されますが、全文ファイルには本文が含まれます。

</details>

5. 全文ファイルのサイズを考えると、LLM で使う方法としてページが推奨しているのはどれですか？
   - A) 数 MiB の全文ファイルを各プロンプトに貼り付ける。最も正確な方法である
   - B) 全文ファイルを複数に分割し、毎回すべて添付する
   - C) モデルにインデックスを参照させ、必要なページだけを取得させる。ほとんどのツールではこの方法が適している
   - D) ダイアグラムビューアーの URL だけを渡し、LLM に残りを推測させる
<details>
<summary>解答を表示</summary>

**解答: C) モデルにインデックスを参照させ、必要なページだけを取得させる。ほとんどのツールではこの方法が適している**

**解説:**
「サイズ」に関する注記では、全文ファイルのサイズは数 MiB あり、「ほとんどのツールでは、書籍全体を 1 つのプロンプトに貼り付けるより、モデルにインデックスを参照させ、必要なページだけを取得させる方が適している」と説明しています。最初のプロンプト例（「…/llms.txt を読み、ドキュメントを見つけて要約する」）がまさにこの使い方です。全文ファイルは、ファイル全体をダウンロードしてチャンクに分ける RAG のインデックス作成などに適しています。

</details>

6. `llms-full-*.txt` のドキュメント単位のチャンク分割が簡単なのはなぜですか？
   - A) 各ドキュメントが独立した ZIP エントリーとして保存されている
   - B) 各ドキュメントの前に `Source: <URL>` を含む区切りブロックがある
   - C) 各ドキュメントが必ず 4,096 文字で分割されている
   - D) ドキュメントが JSON 配列の要素ごとに保存されている
<details>
<summary>解答を表示</summary>

**解答: B) 各ドキュメントの前に `Source: <URL>` を含む区切りブロックがある**

**解説:**
「形式に関する注記」には、「すべてのドキュメントの前に区切りブロックがある」と記載されています。ブロックは破線、`Source: https://www.atomai.click/kubernetes-docs/en/core/01-cluster-architecture` のような URL、もう一つの破線で構成されます。RAG の例のコメントにも「ドキュメントは `Source: <URL>` ブロックで区切られているため、ドキュメント単位のチャンク分割は簡単」とあります。ファイルは ZIP や JSON ではなく、プレーンな Markdown テキストです。

</details>

7. 全文ファイルに含まれるダイアグラム情報を、LLM と人がそれぞれどのように使うと説明されていますか？
   - A) LLM は PNG 画像を直接解析し、人は代替テキストを読む
   - B) LLM はダイアグラムの説明（代替テキスト）を読んで内容を理解する。人はインタラクティブビューアーの URL を開き、Export メニューから PNG/JPEG/WebP、SVG、WebM、Share Card をダウンロードする
   - C) LLM も人も全文ファイルからダイアグラムの情報を得られない
   - D) LLM がビューアーの URL から WebM アニメーションをレンダリングし、人に渡す
<details>
<summary>解答を表示</summary>

**解答: B) LLM はダイアグラムの説明（代替テキスト）を読んで内容を理解する。人はインタラクティブビューアーの URL を開き、Export メニューから PNG/JPEG/WebP、SVG、WebM、Share Card をダウンロードする**

**解説:**
「ダイアグラムは人向け: エクスポートリンク」のセクションでは、全文ファイルには各ドキュメントの Markdown がそのまま含まれるため、すべてのダイアグラムの代替テキストとビューアー URL（`https://www.atomai.click/kubernetes-docs/archmaps/<name>.html`）もテキストに含まれると説明しています。「テキストを扱う LLM は代替テキストと周辺の文章を利用するが、画像にしかないノードやエッジを確実に推測することはできない。人は URL を開き、ビューアーの **Export** メニューから PNG/JPEG/WebP、デュアルテーマの SVG、6 秒のトレースアニメーション WebM、または 1200×630 の Share Card をダウンロードする」とあります。各項目の手順は、Guidebook Roadmap の「Share a diagram」セクションにあります。

</details>

8. ビューアーからエクスポートするダイアグラムファイル（PNG、SVG、WebM、Share Card）について、ページはどのような制限を示していますか？
   - A) エクスポートは、アーキテクチャが検証された正式な証拠として使える
   - B) エクスポートは情報共有用の素材であり、アーキテクチャが検証された証拠ではない
   - C) エクスポートは LLM 専用であり、人は開けない
   - D) エクスポートはドキュメントの正式なリリース形式であり、ソース HTML に置き換わる
<details>
<summary>解答を表示</summary>

**解答: B) エクスポートは情報共有用の素材であり、アーキテクチャが検証された証拠ではない**

**解説:**
このセクションは「エクスポートは情報共有用の素材であり、アーキテクチャが検証された証拠ではありません」と締めくくっています。ダイアグラムのエクスポートは、LinkedIn の投稿や講演用スライドなどでの共有を目的としています。画像があることは、描かれたアーキテクチャが検証済みかどうかを何も示しません。

</details>
