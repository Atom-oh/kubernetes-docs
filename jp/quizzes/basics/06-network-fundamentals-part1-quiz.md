# ネットワークの基礎 パート1クイズ: レイヤーモデル、リンク、ルーティング

> **最終更新日**: 2026年9月14日

リンク層とインターネット／ルーティング層の11種類のプロトコルおよび仕組みに関する理解を確認します。

## 選択問題

1. VPN またはオーバーレイネットワークで、「ping は通るが、大きな応答が止まる」という障害に遭遇しました。最初に何を疑うべきですか。
   - A) DNS TTL が長すぎる
   - B) カプセル化ヘッダーによる実効 MTU の縮小と ICMP の遮断（MTU ブラックホール）
   - C) TCP 輻輳制御アルゴリズムの不一致
   - D) ARP キャッシュの期限切れ

<details>
<summary>答えを表示</summary>

**答え: B) カプセル化ヘッダーによる実効 MTU の縮小と ICMP の遮断（MTU ブラックホール）**

**解説:**
カプセル化によって、経路上で収まる内側のパケットサイズは小さくなります。DF が設定された IPv4 パケットはルーターでフラグメント化できません。従来の PMTUD では、ICMP Type 3 Code 4 が必要です。IPv6 ルーターはパケットをフラグメント化せず、ICMPv6 Packet Too Big（Type 2）を使います。これらのメッセージを遮断するとブラックホールが発生する場合がありますが、PLPMTUD は ICMP に頼らずにサイズを調べることができます。

</details>

2. VIP ベースの HA 構成で、フェイルオーバー直後に新しいアクティブノードが Gratuitous ARP を送るのはなぜですか。
   - A) DHCP サーバーに IP アドレスを再登録するため
   - B) スイッチと隣接ホストの MAC テーブル／ARP キャッシュを更新し、新しいノードを指すようにするため
   - C) ゲートウェイにルーティングテーブルの再計算を強制するため
   - D) TLS セッションを再ネゴシエーションするため

<details>
<summary>答えを表示</summary>

**答え: B) スイッチと隣接ホストの MAC テーブル／ARP キャッシュを更新し、新しいノードを指すようにするため**

**解説:**
VIP は変わりませんが、その所有者や MAC アドレス／ポートの位置が変わります。Gratuitous ARP は IP と MAC の対応を隣接機器に通知し、スイッチは新しいポートで送信元 MAC を学習できます。一部の HA 設計では仮想 MAC を維持します。この更新が遅れると、フェイルオーバーの切り替えに時間がかかります。

</details>

3. OSPF と BGP の違いを最も正確に表す説明はどれですか。
   - A) OSPF はポリシーベースで経路を選択し、BGP は最短経路を計算する。
   - B) OSPF は AS 間ルーティング用で、BGP は AS 内ルーティング用である。
   - C) OSPF は AS 内で Dijkstra 法により最短経路を計算し、BGP はポリシーに基づいて AS 間の経路を選ぶ。
   - D) どちらもリンクステートプロトコルであり、用途だけが異なる。

<details>
<summary>答えを表示</summary>

**答え: C) OSPF は AS 内で Dijkstra 法により最短経路を計算し、BGP はポリシーに基づいて AS 間の経路を選ぶ**

**解説:**
OSPF はリンクステート型の IGP です。エリア内の各ルーターが同じトポロジー情報を共有し、それを使って最短経路を計算します。BGP はパスベクトルプロトコルで、AS_PATH、Local Preference、MED などの属性を使い、「ポリシーが優先する経路」を選択します。Direct Connect は BGP を使用します。Site-to-Site VPN は、対応する構成で BGP または静的ルーティングをサポートします。BGP には AS 内の iBGP セッションもあります。

</details>

4. NAT が「レイヤーモデルに違反する」と言われる理由を最もよく説明しているのはどれですか。
   - A) リンク層のフレームを直接変更するため
   - B) L3 の装置でありながら L4 ポートを書き換え、エンドツーエンド接続という前提を崩すため
   - C) 暗号化されたパケットを復号するため
   - D) ルーティングテーブルを使わないため

<details>
<summary>答えを表示</summary>

**答え: B) L3 の装置でありながら L4 ポートを書き換え、エンドツーエンド接続という前提を崩すため**

**解説:**
ポート変換を行う NAT（PAT/NAPT）は、IP アドレスだけでなくポートも書き換え、セッションごとの対応テーブルに依存します。その結果、直接の P2P 接続が難しくなり、WebRTC は STUN/TURN（ICE）で回避します。クラウドでは、NAT Gateway のポート枯渇やデータ処理料金が実務上の問題になります。

</details>

5. IPv6 をデュアルスタックで導入している組織で、どのセキュリティ上の抜けを確認すべきですか。
   - A) IPv6 は暗号化をサポートしない。
   - B) IPv4 のファイアウォールルールしか管理されておらず、IPv6 経路のルールがない。
   - C) IPv6 アドレスはスキャンしやすい。
   - D) SLAAC によって DHCP サーバーが無効になる。

<details>
<summary>答えを表示</summary>

**答え: B) IPv4 のファイアウォールルールしか管理されておらず、IPv6 経路のルールがない**

**解説:**
デュアルスタックでは、ファイアウォールルールとセキュリティポリシーを2種類維持する必要があります。IPv6 ルールの欠落はリスクですが、IPv6 アドレスがあるだけでインターネットから到達可能になるわけではありません。ルート、セキュリティグループ、NACL は引き続き適用されます。Egress-Only Internet Gateway を使えば、要求していない IPv6 の受信接続を防止できます。

</details>

6. 通常の IPv4 ブロードキャストサブネット上の `192.0.2.130/26` について、正しいネットワークアドレス、ブロードキャストアドレス、ホスト範囲はどれですか。
   - A) ネットワーク `.0`、ブロードキャスト `.255`、ホスト `.1`～`.254`
   - B) ネットワーク `.130`、ブロードキャスト `.193`、ホスト `.131`～`.192`
   - C) ネットワーク `.128`、ブロードキャスト `.191`、ホスト `.129`～`.190`
   - D) ネットワーク `.128`、ブロードキャスト `.190`、ホスト `.129`～`.189`

<details>
<summary>答えを表示</summary>

**答え: C) ネットワーク `.128`、ブロードキャスト `.191`、ホスト `.129`～`.190`**

**解説:**
サブネットマスクは `255.255.255.192` です。ホスト部は6ビットなので、アドレスは64個あります。`.130` は `.128`～`.191` のブロックに含まれます。ネットワークアドレスとブロードキャストアドレスを除くと、通常のホストアドレスは62個です。ここにあるアドレスはすべて `192.0.2` のプレフィックスを持つドキュメント用の例です。

</details>

7. `192.0.2.130/26` のホストには、サブネットへのオンリンクルートがあります。選択されるルーティングテーブルには、`.129` 経由の `198.51.100.0/24`、`.190` 経由の `198.51.100.128/25`、`.129` 経由のデフォルトルートがあります（ゲートウェイは `192.0.2` 内）。宛先 `198.51.100.140` に対し、近隣エントリがない場合、どのルートと ARP 宛先が使われますか。
   - A) デフォルトルートを使い、`192.0.2.129` に ARP する。
   - B) `/25` ルートを使い、`192.0.2.190` に ARP する。
   - C) `/24` ルートを使い、`198.51.100.140` に ARP する。
   - D) `/25` ルートを使い、`198.51.100.140` に ARP する。

<details>
<summary>答えを表示</summary>

**答え: B) `/25` ルートを使い、`192.0.2.190` に ARP する**

**解説:**
3つのリモートルートすべてに一致しますが、`/25` が最長プレフィックスです。ARP で解決するのはオンリンクのゲートウェイなので、フレームはそのゲートウェイの MAC アドレスに送られます。一方、IP の宛先は `198.51.100.140` のままです（NAT がない場合）。デフォルトルートのメトリックを小さくしても、より具体的なルートが優先されます。

</details>

8. `192.0.2.130/26` のホストに、オンリンクの `192.0.2.128/26` ルートと、`192.0.2.129` 経由のデフォルトルートがあります。より具体的なルートも近隣キャッシュのエントリもない場合、`192.0.2.150` へはどのように送信しますか。
   - A) `192.0.2.150` に ARP し、その MAC アドレスに直接送信する。
   - B) すべての IP トラフィックにゲートウェイが必要なので、`192.0.2.129` に ARP する。
   - C) `192.0.2.191` に ARP し、IP パケットをブロードキャストする。
   - D) リンク層の宛先を指定せずに、デフォルトゲートウェイへ送信する。

<details>
<summary>答えを表示</summary>

**答え: A) `192.0.2.150` に ARP し、その MAC アドレスに直接送信する**

**解説:**
選択された `/26` ルートは、この宛先がオンリンクであることを示します。次ホップは宛先ホスト自身です。設定済みのデフォルトゲートウェイが使われるのは、ルート検索でそのゲートウェイが選択された場合だけです。デフォルトゲートウェイが設定されているからといって、ローカルのトラフィックがそこを経由するわけではありません。

</details>

9. 通常の「アドレス総数から2を引く」という計算の例外について、正しい説明はどれですか。
   - A) `/31` では、常に使用可能なエンドポイントが0個になる。
   - B) `/32` では、ホストアドレスと別のゲートウェイアドレスが必ず1つずつ得られる。
   - C) すべてのクラウド `/26` で、通常のホストアドレス62個をすべて割り当てられる。
   - D) 対応するポイントツーポイント `/31` では両方のアドレスを使用し、`/32` は1つのアドレスを示す。クラウドの予約分は別途確認する必要がある。

<details>
<summary>答えを表示</summary>

**答え: D) 対応するポイントツーポイント `/31` では両方のアドレスを使用し、`/32` は1つのアドレスを示す。クラウドの予約分は別途確認する必要がある**

**解説:**
RFC 3021 は、ポイントツーポイント接続の両端に2つの `/31` アドレスを使うことを認めています。`/32` のホストルートは1つのアドレスに一致しますが、それだけでオンリンク到達性が確立するわけではありません。標準の AWS VPC IPv4 サブネットでは5つのアドレスが予約されるため、`/26` で割り当て可能なアドレスは59個です。BYOIP などのモードには別のルールがあります。

</details>

10. UDP traceroute で、中間ルーターから ICMP Type 11 Code 0 が届き、その後、宛先から Type 3 Code 3 が届きました。通常、これは何を意味しますか。
   - A) プローブの TTL が経路上で期限切れになり、その後のプローブが宛先の未使用 UDP ポートに到達した。
   - B) 各ホップで宛先が UDP データを返信した。
   - C) ルーターがパス MTU の問題を報告し、その後、宛先が TLS を完了した。
   - D) traceroute が送信プローブをすべて ICMP Echo Request に変更した。

<details>
<summary>答えを表示</summary>

**答え: A) プローブの TTL が経路上で期限切れになり、その後のプローブが宛先の未使用 UDP ポートに到達した**

**解説:**
プローブのプロトコルと応答のプロトコルは異なることがあります。UDP プローブに対して ICMP エラーが返る場合があります。ICMP Echo や TCP SYN を使う traceroute でも、中間ホップでは Time Exceeded が使われますが、最終応答は Echo Reply、TCP SYN/ACK、または RST になることがあります。Fragmentation Needed は Type 3 Code 4 であり、この設問にあるどちらのコードでもありません。

</details>

11. traceroute のあるホップでは `* * *` と表示されますが、その後のホップと宛先から応答があります。妥当な結論はどれですか。
   - A) 応答しなかったルーターが、エンドツーエンドの全トラフィックを破棄している。
   - B) 待ち時間内に、そのプローブに一致する応答が届かなかった。エンドツーエンドのパケット損失と結論付けるには、さらに証拠が必要である。
   - C) 送信経路と戻り経路は同一である。
   - D) あらゆるアプリケーションパケットのサイズが経路 MTU に収まる。

<details>
<summary>答えを表示</summary>

**答え: B) 待ち時間内に、そのプローブに一致する応答が届かなかった。エンドツーエンドのパケット損失と結論付けるには、さらに証拠が必要である**

**解説:**
フィルタリング、応答の抑制／レート制限、戻り経路での損失によってタイムアウトが発生することがあります。宛先やアプリケーションの結果と照らし合わせ、プローブを繰り返してください。RTT には戻り経路も含まれます。また、小さなプローブが成功しても、大きなパケットで PMTU ブラックホールが起きていないとは限りません。

</details>
