# VictoriaMetrics クイズ

> レビュー基準: VictoriaMetrics 1.151.0 · stack chart 0.92.1

1. Prometheus のクエリを VictoriaMetrics に移行する際、正しい説明はどれですか？
   - A) すべてのワークロードで圧縮率が正確に 7 倍向上する
   - B) すべてのインストール環境に固定の 1 億時系列上限がある
   - C) MetricsQL は PromQL と意図的に異なるため、実際のクエリを比較する
   - D) Prometheus で保持できるデータは最大 15 日間である

<details>
<summary>解答を表示</summary>

**解答: C**

構文が似ていても、rate/increase、NaN、スカラー、API の動作まで同一とは限りません。ベンチマークでは実際のバージョン、データ、ハードウェアを使ってください。保持期間の既定値は上限ではありません。

</details>

2. VictoriaMetrics クラスターのストレージ／クエリのデータプレーン構成要素ではないものはどれですか？
   - A) vminsert
   - B) vmstorage
   - C) vmselect
   - D) VictoriaMetrics Operator

<details>
<summary>解答を表示</summary>

**解答: D**

vminsert は書き込みを振り分け、vmstorage はデータを保存し、vmselect はクエリを処理します。Operator は Kubernetes リソースを調整する別個の制御コンポーネントです。

</details>

3. vmagent の役割は何ですか？
   - A) すべての永続ストレージを置き換える
   - B) ダッシュボードをレンダリングする
   - C) メトリクスを収集し、remote-write の送信先へ転送する
   - D) Alertmanager の通知ルーティングを置き換える

<details>
<summary>解答を表示</summary>

**解答: C**

vmagent のキューは障害中のデータをバッファリングしますが、容量には上限があります。設定されたディスク上限に達すると古いキューデータが破棄され、`emptyDir` は Pod の置き換え時に失われます。永続化と監視は、それぞれ別に設計する必要があります。

</details>

4. `keep_last_value(q)` の動作と、注意すべき点はどれですか？
   - A) 保存済みの最大値を返す
   - B) 評価時の欠損箇所を以前の値で補完するため、テレメトリの欠落を隠すことがある
   - C) 失われた scrape サンプルをすべて復元する
   - D) 可用性アラートが正常であることを保証する

<details>
<summary>解答を表示</summary>

**解答: B**

欠損値の補完は、その意味が意図に合う場合にだけ使ってください。古い正常値を保持するとデータ収集の欠落を覆い隠すことがあります。データ欠落は別途監視してください。

</details>

5. `dedup.minScrapeInterval` が制御するのはどれですか？
   - A) 対象を scrape するスケジュール間隔
   - B) 同じ時系列について、離散区間ごとにサンプルを 1 つ残すこと
   - C) 汎用のロスレス圧縮
   - D) アラート評価の頻度

<details>
<summary>解答を表示</summary>

**解答: B**

この間隔を設定すると、重複したサンプルだけでなく、正当な高解像度サンプルも削除される場合があります。vmstorage と vmselect の設定、および採用するストレージ／scraper のレプリケーション方式を整合させてください。

</details>

6. 単一ノードモードとクラスター モードは、どのように選択すべきですか？
   - A) 常にクラスター モードを選ぶ
   - B) 負荷、アクティブ時系列数と churn、クエリ、保持期間、復旧要件を計測・評価する
   - C) 1 日あたり 1 億サンプルを全環境共通の境界値として使う
   - D) 単一ノード モードにはクエリ API がない

<details>
<summary>解答を表示</summary>

**解答: B**

単一サーバーの処理能力と、insert、storage、select を個別にスケールするコストを評価してください。ストレージを複製することやプロセスを 2 つ動かすことだけでは、検証済みのサービス高可用性は得られません。

</details>

7. `vminsert` の `replicationFactor=2` が要求するのはどれですか？
   - A) ストレージ メンバーの合計を正確に 2 台にする
   - B) 実際の可用性と履歴の条件に従い、異なるストレージ メンバーに 2 つのコピーを保持する
   - C) ちょうど 2 台のメンバーでクエリを実行する
   - D) 圧縮率を 2 倍にする

<details>
<summary>解答を表示</summary>

**解答: B**

ストレージ メンバー 1 台の障害中も 2 コピーを維持するには、少なくとも 3 台に加えて、適切なキャパシティと障害ドメインの条件が必要です。vmselect と dedup の設定も整合させてください。このフラグは過去データを補完せず、縮退時の書き込みが損失しないことも、バックアップの代わりになることも保証しません。

</details>

8. MetricsQL の `default` 演算子の適用範囲はどれですか？
   - A) 常に正しいサービスラベルを作成する
   - B) 右辺の式で欠損点を補う。欠損データは自動的にトラフィック 0 を意味しない
   - C) すべての比率が意味のある値になることを保証する
   - D) メトリクスの取り込み間隔を変更する

<details>
<summary>解答を表示</summary>

**解答: B**

`default 0` を、あらゆるエラー率の問題に対する万能策として追加しないでください。status ラベルを一貫して集約し、分母に系列が存在することが分かっている場合だけ欠損した分子を補い、トラフィックが 0 の状態を除外します。組み込みの例では、正常、すべて失敗、10% 失敗のトラフィックに対して、それぞれ 0、1、0.1 が得られます。サービスが存在しない場合やトラフィックが 0 の場合、そのサービスは結果に現れません。

</details>

9. vmalert の役割は何ですか？
   - A) すべてのアプリケーション メトリクスを収集する
   - B) すべての長期サンプルを保存する
   - C) アラート／記録ルールを評価し、設定済みの通知先へアラートを送る
   - D) Grafana ダッシュボードをレンダリングする

<details>
<summary>解答を表示</summary>

**解答: C**

ルールの入力元や exporter、データソース URL、状態の永続化、通知先／ルーティングの設定が必要です。再起動回数が多いだけでは、CrashLoopBackOff だとは判断できません。記録ルールで派生系列を作成しても、生データの圧縮や削除は行われません。

</details>

10. vmbackup の正しい手順はどれですか？
    - A) vminsert の設定だけをバックアップする
    - B) 対応するストレージ ディレクトリからスナップショットを読み取り、別個のバックアップ先を保護する
    - C) 確認せずに任意の RWO PVC を任意のノードへマウントする
    - D) ストレージのレプリケーションを完全なバックアップとして扱う

<details>
<summary>解答を表示</summary>

**解答: B**

すべての vmstorage メンバーを別々の prefix へバックアップするか、単一ノード構成であれば対象のストアをバックアップします。S3、GCS、Azure、ローカルの保存先を利用できます。配置先との同居関係や PVC の ID、ワークロードの認証情報、保持期間、実際の復元を確認してください。ローカルのスナップショットは独立したコピーではありません。

</details>
