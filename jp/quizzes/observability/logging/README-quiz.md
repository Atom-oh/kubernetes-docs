# ロギング概要クイズ

> **最終更新**: September 13, 2026

1. 構造化 JSON ログについて正しい説明はどれですか?

   - A) パースは一切不要である
   - B) 常にバイト数が少なくなる
   - C) 明示的なフィールドは分析に役立つが、デコード、フレーミング、フィールドマッピングは依然として重要である
   - D) 機密データをすべて自動的にマスクする

<details>
<summary>解答を表示</summary>

**解答: C**

検証済みのイベントスキーマを使用し、通常は 1 行あたり 1 つのエンコード済みイベントとします。JSON はプレーンテキストより大きくなることがあり、生データとパース済みデータの両方にデータ取り扱いポリシーが必要です。

</details>

2. TRACE から FATAL までは、どこでも 0 から 5 の番号が付けられていますか?

   - A) いいえ。フレームワークによって異なり、OpenTelemetry は 1〜24 の重大度範囲を使用し、0 は未指定である
   - B) はい、すべての言語で同じである
   - C) はい、Kubernetes においてのみ同じである
   - D) FATAL は常に 0 である

<details>
<summary>解答を表示</summary>

**解答: A**

架空の数値スケールをコピーするのではなく、重大度の意味をマッピングしてください。ログレベルだけで回復可能性は判断できず、本番のログをすべて WARN に引き上げると証跡を失うおそれがあります。

</details>

3. Linux コンテナログの一般的なデフォルト配置はどれですか?

   - A) 実ファイルは /var/log/containers、シンボリックリンクは /var/log/pods
   - B) 実ファイルは /var/log/pods、互換用のシンボリックリンクは /var/log/containers
   - C) すべてのランタイムは /var/lib/docker にのみ書き込む
   - D) kubectl logs には無制限のアーカイブが含まれる

<details>
<summary>解答を表示</summary>

**解答: B**

元のパスは逆になっていました。podLogsDir や OS、ランタイムによって配置は変わり得ます。ローテーションや --previous は中央集約された履歴アーカイブを作成しません。

</details>

4. バックエンドのコストを公平に比較するには何が必要ですか?

   - A) S3 の GB 単価のみ
   - B) 請求額を最小にするため常に Loki を選ぶこと
   - C) セルフマネージドのクエリは無料だと仮定すること
   - D) 同一のワークロードについて、取り込み、保持/インデックス対象データ、コンピュート、クエリ、リクエスト、ネットワーク、リカバリ、運用を比較すること

<details>
<summary>解答を表示</summary>

**解答: D**

以前の 2025 年および 100 GB の数値は単位が混在しており、再現可能な構成が示されていませんでした。これらは実測された本番結果ではなく、日付を更新するだけでは解決しません。

</details>

5. トレースコンテキストはログにどのように付与すべきですか?

   - A) レコードごとに無関係な ID を生成する
   - B) 実際のアクティブなコンテキストを使用する。示されている trace/span ID は 32/16 桁の 16 進文字で構成され、すべてゼロにはなり得ない
   - C) すべての起動時レコードで trace ID を必須にする
   - D) セッショントークンを span ID として使用する

<details>
<summary>解答を表示</summary>

**解答: B**

トレースを伴わないイベントも有効です。JSON のフィールド名は宛先のモデルへのマッピングが必要であり、ID だけで分散トレースが構成されたり相関が証明されたりするわけではありません。

</details>

6. 図示されたパイプラインにおいて、より安全な処理の選択はどれですか?

   - A) HealthCheck を含む行をすべて破棄する
   - B) アプリケーションの JSON をテナント識別情報として信頼する
   - C) アプリのフィールドを信頼できるメタデータから分離し、マスキング/フィルタリング、オフセット、バッファ、リトライを検証する
   - D) バッファリングによって損失と重複がすべて防げると仮定する

<details>
<summary>解答を表示</summary>

**解答: C**

この Fluent Bit のサンプルはクラシック形式のフィルタ断片です。Keep_Log はマスキング対象となる別のコピーを保持します。失敗したヘルスチェックは貴重な証跡になり得るほか、配信保証は経路全体に依存します。

</details>

7. 規制上の保持期間はどのように決定すべきですか?

   - A) 該当するレコード種別、法域、契約、リーガルホールド、承認済みポリシーに基づいて決定する
   - B) すべての財務系ログを 7 年間
   - C) すべての医療系ログを 6 年間
   - D) 特定のバックエンドを採用すればコンプライアンスが証明される

<details>
<summary>解答を表示</summary>

**解答: A**

業界のラベルは完全な法的ルールではありません。レプリカ、オブジェクトバージョン、バックアップ、エクスポートを保持/削除/アクセスの計画に含め、リストアをテストしてください。

</details>

8. sidecar と DaemonSet について正しいものはどれですか?

   - A) どちらもテナント分離を保証する
   - B) emptyDir は Pod の削除後も残る
   - C) DaemonSet はすべてのノードのログが配信されたことを証明する
   - D) sidecar はファイル出力のみのアプリに有効な場合がある。ただしスケジューリング、共有ストレージ、ライフサイクル、セキュリティの検証は依然として必要である

<details>
<summary>解答を表示</summary>

**解答: D**

emptyDir は Pod 内のコンテナ再起動をまたいで残りますが、Pod の削除後は残りません。DaemonSet は対象となるノードに配置され、ロールアウトが重複することもあります。また、複数の経路があるとレコードが重複し得ます。

</details>

9. ストレージ/クライアントに関する記述で正しいものはどれですか?

   - A) OpenSearch はどのデプロイでもスナップショットにのみ S3 を使用する
   - B) デプロイ/インデックス/クエリの設計が重要である。UltraWarm は S3 とキャッシュを使用し、Promtail は表明された EOL 後に移行が必要である
   - C) CloudWatch のすべてのログクラスは同一の機能を持つ
   - D) データセットがなくても圧縮率のランキングは有効である

<details>
<summary>解答を表示</summary>

**解答: B**

実際のデプロイモデルとクエリ要件を比較してください。Promtail の EOL は 2026-03-02 であり、告知では lambda-promtail が別扱いとされています。バックエンドを選ぶだけではコストやコンプライアンスは保証されません。

</details>

10. EKS のコントロールプレーン監査ログを有効にすると何が確立されますか?

   - A) すべてのリクエストとボディが損失なく記録される
   - B) ワーカーの DaemonSet がマネージド API サーバーのホストを読み取る
   - C) 監査レコードはポリシーに従い、ベストエフォートの CloudWatch 配信経路を通るため、検証が必要である
   - D) アプリケーションの stdout 収集が自動的に完全になる

<details>
<summary>解答を表示</summary>

**解答: C**

非同期の更新ステータス、実際のストリーム、保持/アクセスを確認してください。Fargate はマネージドのルーターを使用し、Container Insights のパフォーマンスログはアプリケーションの stdout/stderr とは別物です。

</details>
