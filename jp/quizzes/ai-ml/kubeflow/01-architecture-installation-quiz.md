# EKS 上の Kubeflow アーキテクチャとインストール クイズ

ベースライン: Community Distribution 26.03.1 / Dashboard 2.0.0 / KFP 2.16.1。

## 選択式問題

1. Kubeflow の 2026 年 8 月 17 日の CNCF 卒業は何を確立するものですか?

   - A) すべての EKS デプロイメントの自動的なコンプライアンス準拠
   - B) 独立したセキュリティ監査を含む、プロジェクトの成熟度とガバナンス
   - C) 今後セキュリティ更新は不要であること
   - D) 設定なしで保証されるテナント分離

<details>
<summary>回答を表示</summary>

**回答: B) 独立したセキュリティ監査を含む、プロジェクトの成熟度とガバナンス**

卒業はプロジェクトに関するものです。デプロイメントのセキュリティ、分離、規制コンプライアンスについては、依然として個別の評価が必要です。
</details>

2. この章ではどのリリースベースラインが使用されていますか?

   - A) AWS Kubeflow 1.7 と Community 26.03.1 は同一である
   - B) KFP 2.16.1 と Dashboard 2.0.0 を含む Community 26.03.1
   - C) すべてのコンポーネントがバージョン 26.03.1 を使用している
   - D) リリースを固定しない master ブランチ

<details>
<summary>回答を表示</summary>

**回答: B) KFP 2.16.1 と Dashboard 2.0.0 を含む Community 26.03.1**

ディストリビューションとコンポーネントのバージョンは異なります。コミュニティのリリースカレンダーでは年間およそ 2 回のベースリリースが計画されており、サポートは SLA ではなくベストエフォートとして説明されています。
</details>

3. Profile の resourceQuotaSpec.hard を省略するとどうなりますか?

   - A) コントローラーがデフォルトの GPU クォータを設定する
   - B) Istio が同等の CPU クォータを提供する
   - C) Profile コントローラーが ResourceQuota を作成しない
   - D) その namespace に無制限の AWS IAM 権限が付与される

<details>
<summary>回答を表示</summary>

**回答: C) Profile コントローラーが ResourceQuota を作成しない**

クォータはオプションです。hard を空にすると、コントローラー管理のクォータは作成されません。RBAC、network policy、ストレージ、AWS アクセスはそれぞれ別の境界です。
</details>

4. 古い AWS ディストリビューションのインストールガイドに従う前に確認すべきことは何ですか?

   - A) 最近のリポジトリの活動状況のみ
   - B) ダッシュボードのロゴが変更されたかどうか
   - C) そのリリースに互換性があり、必要なイメージが引き続き利用可能かどうか
   - D) すべてのコンポーネントが CRD であるかどうか

<details>
<summary>回答を表示</summary>

**回答: C) そのリリースに互換性があり、必要なイメージが引き続き利用可能かどうか**

調査した v1.7.0-aws-b1.0.3 リリースでは、削除された OIDC イメージが利用できないため新規インストールが失敗することが明示的に警告されています。これは検証済みの 26.03.1 向け手順ではありません。
</details>

5. 現行の KFP における S3 アイデンティティについて、裏付けのある記述はどれですか?

   - A) KFPv2 では一律に静的な IAM ユーザーキーが必要である
   - B) fromEnv は静的なアクセスキーのみを受け付ける
   - C) 現行ガイドは IRSA を記載しているが、実際の SDK、ServiceAccount、ロールの信頼関係は依然として検証が必要である
   - D) Profile が自動的に Pod Identity の関連付けを作成する

<details>
<summary>回答を表示</summary>

**回答: C) 現行ガイドは IRSA を記載しているが、実際の SDK、ServiceAccount、ロールの信頼関係は依然として検証が必要である**

KFP 2.16.1 は fromEnv を Go Cloud に委譲しており、その固定されたデフォルトは AWS SDK v2 の資格情報チェーンを使用します。このソースコードの調査は、EKS Pod Identity でのデプロイメントを証明するものではありません。
</details>

6. ダッシュボードはどのような役割を担いますか?

   - A) すべてのモデルを自動的にトレーニングしてデプロイする
   - B) 各コンポーネントのインターフェイスへのナビゲーションを提供する
   - C) すべてのアプリケーションの認可を置き換える
   - D) すべてのパイプラインアーティファクトを CRD に保存する

<details>
<summary>回答を表示</summary>

**回答: B) 各コンポーネントのインターフェイスへのナビゲーションを提供する**

ワークロードコントローラーとアプリケーション API はそれぞれ独自の処理を行います。KFP API も永続化を利用しており、その Run および Experiment という概念は一律に CRD であるとは限りません。
</details>

## 記述式問題

7. Dashboard v2 への移行中に、Profile オブジェクトとその CRD を保持すべき理由は何ですか?

<details>
<summary>回答を表示</summary>

Profile コントローラーは namespace の所有権を設定します。Profile を削除すると、その namespace とリソースにまで削除が波及する可能性があります。テナントの Profile や namespace を削除することなく、リリース固有の手順に従って古いコントローラーのリソースをクリーンアップしてください。
</details>

8. Profile のオーバーレイのレンダリングが成功したことは何を証明し、何が未検証のまま残りますか?

<details>
<summary>回答を表示</summary>

選択した Kustomize の入力からマニフェストが生成されることを証明します。レビューしたオーバーレイでは、Dashboard 2.0.0 のイメージを含む 14 個のリソースが生成されました。ただし、API の admission、コントローラーの準備状態、テナント分離、EKS 上での S3 アクセスは証明されません。マネージドサービスへの置き換えについても、アイデンティティ、互換性、ネットワーク、コスト、移行に関する確認が必要です。
</details>
