# ワークショップ：PII モデルとマスキングパイプラインを評価する

> **最終更新日**: 2026年9月15日

実行可能な例では、合成レコードと手作業で作成した予測を CPU 上で使用します。ここに示す数値は、学習済みモデルの性能を表すものではありません。

学習損失が低下しても、PII を適切に除去できているとは限りません。モデルは氏名を検出してもメールアドレスを見逃したり、アノテーション方針では機微情報とみなされない文書番号をマスキングしたりすることがあります。この章では、**エンティティ抽出と、抽出結果に対する置換の両方**を評価し、エラーを次のデータ実験につなげます。

先に [QLoRA ワークショップ](05-qlora-finetuning-workshop.md)と[データ拡張ワークショップ](06-data-augmentation-workshop.md)を読んでください。コマンドはリポジトリのルートから実行し、Python 3.12 を使用します。

## 1. モデルと処理の責任を切り分ける

この例のモデルは、文書全体を書き換えるのではなく、`TYPE<TAB>ORIGINAL` 形式の候補を出力します。

| 段階 | 入力 → 出力 | 確認事項 |
| --- | --- | --- |
| 抽出 | ソース → 型と値の候補 | 抽出漏れ、誤った型、実在しない値 |
| 検証 | 候補 → ソースと一致する許可済み候補 | 構文、長さ、許可された型、ソースとの一致 |
| 置換 | ソース／候補 → マスキング済みテキスト、マッピング、スパン | 繰り返し、部分的なカバー範囲、衝突、重複 |
| 残存情報の確認 | マスキング済みの結果 → 承認またはレビュー | 独立したルール／検出器、方針、未対応の入力 |
| 提供 | 承認済み文書 → 下流システム | マッピングを含めないこと、アクセス制御、ログの範囲 |

ソースと照合すれば、候補の文字列がソース内に存在することは確認できます。しかし、その候補が意味的に正しい型であることや、ほかの PII を見落としていないことまでは確認できません。検出器を複数組み合わせても、それぞれのエラーが独立するわけではありません。

`pseudonymize_text()` は、元に戻せるトークンの対応表を作成します。`[PERSON_1]` の対応表を保持することと、復元機能を持たせずに値を取り除くことは、目的が異なります。対応表を破棄しただけでは、残った文脈から個人を特定できないとは限りません。

## 2. 学習・検証・最終テストの役割を割り当てる

1. **学習:** パラメーターを更新し、学習時のデータ拡張を適用する。
2. **検証:** ランク、学習率、エポック／ステップ数、データの混合、出力ルールを選定する。
3. **固定したテストセット:** 選定したモデルと処理方針を評価する。
4. **チャレンジセット:** OCR、長文書、見慣れないテンプレート、希少な型、埋め込み指示、その他の難しい条件を個別に調べる。

最終テストの失敗を次のモデル選定に使った場合、そのテストセットは開発プロセスに取り込まれています。変更を記録し、別の評価バージョンを用意してください。文書ファミリー、顧客、テンプレート、時期など、どの軸でデータを分割したかも記録します。

**過去の `src/train.py` は、実行のたびに `test_records` を使ってベースラインと調整後の予測を評価します。この挙動のまま、繰り返し実行する HPO ループとして使わないでください。**

調整処理では、検証データに基づく候補選定と、別に記録した最終テストのステップが必要です。以下の CPU 演習では、このランチャーは実行しません。

## 3. CPU 上で「F1 は向上したが、問題は残る」を再現する

次の2つの文書を使います。

- 合成した氏名と `example.com` のメールアドレスにアノテーションを付けた陽性文書。
- この方針では文書番号をPIIとみなさない陰性文書。

ベースラインは氏名だけを検出します。候補モデルは氏名とメールアドレスを検出しますが、陰性文書の番号を誤ってアカウントとして分類します。予測はモデルを呼び出さずに手作業で作成するため、指標の計算を確認できます。どちらの言語版でも、同じ合成韓国語のフィクスチャを使用します。

```bash
cd examples/ai-ml/qwen-pii-finetuning
mkdir -p "${XDG_CACHE_HOME:-$HOME/.cache}"
export PII_EVAL_DIR="$(mktemp -d "${XDG_CACHE_HOME:-$HOME/.cache}/pii-evaluation.XXXXXX")"
python3 - <<'PY'
import json
import os
from pathlib import Path

out = Path(os.environ["PII_EVAL_DIR"])
records = [
    {
        "id": "positive-1",
        "source_text": "담당자 김가상, 이메일 synthetic.ko.01@example.com",
        "entities": [
            {"type": "PERSON", "original": "김가상"},
            {"type": "EMAIL", "original": "synthetic.ko.01@example.com"},
        ],
        "target_tsv": "PERSON\t김가상\nEMAIL\tsynthetic.ko.01@example.com",
    },
    {
        "id": "negative-1",
        "source_text": "문서번호 DOC-2026-001의 처리 상태를 확인합니다.",
        "entities": [],
        "target_tsv": "",
    },
]
baseline = [
    {"id": "positive-1", "content": "PERSON\t김가상", "parse_success": True},
    {"id": "negative-1", "content": "", "parse_success": True},
]
candidate = [
    {
        "id": "positive-1",
        "content": records[0]["target_tsv"],
        "parse_success": True,
    },
    {
        "id": "negative-1",
        "content": "ACCOUNT\tDOC-2026-001",
        "parse_success": True,
    },
]
for name, rows in (
    ("gold", records), ("baseline", baseline), ("candidate", candidate)
):
    with (out / f"{name}.jsonl").open("x", encoding="utf-8") as stream:
        for row in rows:
            stream.write(json.dumps(row, ensure_ascii=False) + "\n")
PY

for phase in baseline candidate; do
  python3 -m src.evaluate \
    --test-jsonl "$PII_EVAL_DIR/gold.jsonl" \
    --predictions-jsonl "$PII_EVAL_DIR/$phase.jsonl" \
    --output-json "$PII_EVAL_DIR/$phase-metrics.json" \
    --environment cpu-demo --phase "$phase-demo" \
    --model-id synthetic-fixture-no-model \
    --duration-seconds 0 --hourly-usd 0
done

python3 - <<'PY'
import json
import os
from pathlib import Path

out = Path(os.environ["PII_EVAL_DIR"])
for phase in ("baseline", "candidate"):
    m = json.loads((out / f"{phase}-metrics.json").read_text())["metrics"]
    print(phase, json.dumps({
        "entity": m["entity"],
        "leaked_documents": m["documents"]["leaked"],
        "extra_pairs": m["entities"]["over_redacted"],
        "round_trip": m["tokenization"]["round_trip_rate"],
    }))
PY
```

`--test-jsonl` は評価 CLI の引数名です。ここでは手作業で作成した演習用ファイルを指定しており、本番用の最終ホールドアウトを指定しているわけではありません。

期待される結果:

| 指標 | ベースライン | 候補 |
| --- | ---: | ---: |
| TP / FP / FN | 1 / 0 / 1 | 2 / 1 / 0 |
| 適合率 | 1 | 2/3 |
| 再現率 | 1/2 | 1 |
| エンティティF1 | 2/3 | 0.8 |
| ゴールドラベルのPIIを一部でも見逃した文書 | 2件中1件 | 2件中0件 |
| 余分に抽出されたペア | 0 | 1 |
| 往復変換率 | 1 | 1 |

候補モデルは F1 を向上させる一方で、文書番号のマスキングを新たに引き起こします。どちらの予測も往復変換には成功しています。**値を復元できても、PII 検出の品質が保証されるわけではありません**。所要時間と時間単価がゼロなのは、この手作業のフィクスチャについての記述であり、GPU 学習が無料だという意味ではありません。

## 4. 各指標の単位を確認する

パッケージの `entity` と `per_type` 指標は、文書単位の `(TYPE, ORIGINAL)` の集合を比較します。同じペアが文書内で繰り返されても、1 回として数えます。独立したスパンアノテーションに基づく NER F1 ではありません。

| 指標 | 用途 | 確認すべき制約 |
| --- | --- | --- |
| 型別再現率 | 抽出漏れがある PII カテゴリを見つける | 評価した希少エンティティの数を報告する |
| 型別適合率 | マスキング対象に誤って含めた非機微テキストを特定する | 一貫したアノテーション方針が必要 |
| 文書リーク率 | ゴールドラベルの情報に未検出がある文書の割合 | ゴールドラベルに含まれない PII は測定できない |
| エンティティリーク率 | ゴールド値に一致する出現箇所全体の検出率 | オフセット付きゴールドではなく、値の検索からスパンを推定する |
| `over_redaction_rate` | FP ÷ 予測ペア数 | 不要に削除した文字数の割合ではない |
| `hallucination_rate` | ソースに存在しない、許可済み TSV 候補 | 許可されない型や通常の文章は分母に含まれない |
| 解析成功率 | 呼び出し側から渡される形式処理の状態 | 現在のヘルパーは、有効な行の一部しか含まない出力も受け入れる場合がある |

厳格なサービング用パーサーを設計し、すべての行を検証してください。不正な行、途中で切れた生成結果、入力長の違反は、明示的なエラーとして返します。不正な行を黙って捨てた結果を「PII は見つからなかった」と扱ってはなりません。現在の `parse.success_rate` は、このような厳格な処理が実装されていることを証明するものではありません。

実運用の文書にゴールドアノテーションがなければ、同じゴールドベースのリーク率は算出できません。レビュー済みサンプル、残存情報を検出する仕組み、棄却率やレビュー率を観察し、それぞれが実際に何を測定するのかを明確にしてください。

## 5. エラーを次のデータ実験につなげる

アクセス制御された評価用ワークスペースで、文書単位のエラーを調べてください。通常のログにはソーステキストを記録せず、エラーカテゴリ、長さの区分、言語、テンプレート ID、集計値を残します。

| 観測されたエラー | 最初に調べること | 次の実験 |
| --- | --- | --- |
| 氏名は検出するが、アカウントを見逃す | 型別の件数とアノテーション漏れ | アカウントを含む文脈の学習例を追加する |
| 空白を含む氏名や OCR で失敗する | ソースとラベルの表記形式の整合性 | ソースとラベルを一緒に拡張する |
| 文書番号をアカウントとして分類する | 陰性例の網羅性と文脈上の違い | 数字の文脈をそろえた陽性例と陰性例を追加する |
| 長文書の末尾にある PII を見逃す | プロンプトの切り詰めと生成予算 | チャンク境界、オーバーラップ、オフセットの再構築を評価する |
| 見慣れない氏名で結果が悪い | 学習データとテストデータ間のエンティティ重複 | エンティティ単位で分離した評価と、新たな学習データ群を用意する |
| 新しいレイアウトで結果が悪い | テンプレートの分離 | テンプレート単位で分離した評価と、承認済みテンプレートによる学習を行う |
| ソースに埋め込まれた指示に従う | 文書をデータとして扱う方法 | 埋め込み指示を含む合成例と出力スキーマの検査を追加する |
| 再現率が下がる一方で損失が減少する | 汚染された検証データ、過学習、出力制限 | チェックポイントと早期終了の基準を比較する |

失敗したテスト例を学習データにコピーし、同じテストで改善したと主張してはいけません。エラー分析用データが開発に使われたことを記録し、新しい最終評価セットを用意してください。

## 6. 学習時と推論時の系列長を合わせて設計する

`max_sequence_length=1024` は、文書が 1,024 文字まで入力できることを意味しません。チャットテンプレート、システム指示、ソーステキスト、生成するターゲットのすべてがトークナイザーの予算を消費します。韓国語、英語、数字では、文字数に対するトークン数の比率も異なります。

- 学習時の切り詰めによって、教師ありターゲットのトークンがすべて取り除かれないことを確認する。
- 推論時に切り詰められた入力領域にある PII を、存在しないものとして扱わない。
- チャンク化では、ソースのオフセット、重複箇所の突き合わせ、境界をまたぐエンティティ、同じ値が繰り返し現れる場合への対応が必要。
- オーバーラップだけで十分だと決めつけず、境界をまたぐ PII を意図的に含めてテストする。
- 入力長の超過や不完全な出力を明示し、部分的な結果を完全なものとして扱わない。

## 7. 測定前に受け入れ基準の表を作成する

以下は、チームが証拠と基準を記録するための**テンプレート**です。リポジトリで達成済みの性能や、どのタスクにも当てはまる数値基準を示すものではありません。

| 領域 | 証拠 | 不十分な場合の対応 |
| --- | --- | --- |
| ラベルと分割 | アノテーションのバージョン、ファミリー／分割／ハッシュ、サブグループ件数 | 評価を再構築する |
| 候補の選定 | 検証結果の比較、変更した変数、判断 | 別の管理された実験を実施する |
| 最終品質 | ロック済みテストの型別結果とエラー件数 | デプロイを保留する |
| 出力仕様 | 空、不正、途中で切れた応答のテスト | 解析／棄却処理を修正する |
| 処理方針 | 置換スパン、マッピングのライフサイクル、残存情報の確認 | 方針または処理を修正する |
| 運用時の挙動 | 長さ別のレイテンシ、メモリ、タイムアウト、スループット | 容量と長さの上限を調整する |
| 再現性／復旧 | ベースモデル／トークナイザーのリビジョン、アダプターのハッシュ、環境、以前のバージョン | パッケージ化を完了する |

タスクに適した F1、再現率、レイテンシーの基準を**評価前に**決めてください。小さなサンプルでエラーが見つからなくても、実際のエラー率がゼロだとは言えません。サブグループの結果には、分子と分母の両方を示してください。

## 8. SageMakerの成果物からサービング用パッケージへ

トレーニングジョブが `Completed` になったことが示すのは、ジョブが終了したということだけです。エンドポイントの作成、アダプターの読み込み、出力の検証、マスキング済み結果の承認は、それぞれ別の手順です。

1. `/opt/ml/model` と MLflow から、アダプター、設定、集計結果を保存する。
2. 正確なベースモデル／トークナイザーのリビジョン、チャットテンプレート、量子化設定、パーサーのバージョンをアダプターとともに記録する。
3. 想定する環境で、再読み込みと決定論的デコードをテストする。アダプターだけでは、単独で動作する完全なベースモデルにはなりません。
4. シャドーまたは限定的なカナリア運用で、入力長、出力形式、エラー率を観察する。
5. **モデル + トークナイザー + パーサー + 処理方針**をひとまとまりとしてバージョン管理し、まとめてロールバックできるようにする。

この章では、エンドポイントや厳格なリリースラッパーの実装・デプロイは行いません。実際にデプロイする場合は、CloudWatch、MLflow autolog／トレース、エラー処理、リクエストトレースを通じて、ソース、生成結果、マッピングが露出しないかもテストしてください。アダプターには学習データの影響が反映されるため、共有前に個別のレビューが必要です。

## 理解度を確認する

1. F1が高い候補をすぐにデプロイしてはいけないのはなぜですか？ **陰性文書でマスキングが追加されており、合成文書2件では代表性のある評価にならないからです。**
2. 往復変換率が100%なら、すべてのPIIが除去されたと言えますか？ **いいえ。置換された値の復元に成功しただけかもしれません。**
3. 同じテストを使って複数のランクを選定した場合はどうなりますか？ **選定に使われているため、独立した最終テストではなくなります。**
4. ソースと一致する候補なら、必ずPIIですか？ **いいえ。文書番号が反例です。**
5. ラベルのないトラフィックで、この評価器のリーク率をモデル出力だけから計算できますか？ **いいえ。ゴールドアノテーションが必要です。**
