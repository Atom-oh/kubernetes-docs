# 上級ネットワーキング学習パス

> **リソース確認日**: 2026年9月15日
>
> **環境**: ホスト演習には使い捨ての Ubuntu Server 24.04 LTS または Rocky Linux 9 の VM を使用します。ルーティング／EVPN ツールとクラウド環境には、各章で別途定める前提条件があります。

これらの上級ワークブックは[初級コース](../beginner/README.md)に続く内容です。プロトコルの原則をコードやパケットに結び付けたうえで、証拠を使ってルーティングポリシー、Linux の性能、クラウド設計を評価します。

上級レベルの目標は、**あるべき状態を定義し、観測によって仮説を検証し、変更の影響と復旧方法を説明できること**です。決まった期間学習したり、認定資格を取得したりするだけで、この能力が保証されるわけではありません。

## 受講前の確認 {#entry-check}

次の項目を説明し、再現できるようになったら、第 1 章に進んでください。

- IP、サブネット、ゲートウェイ、DNS の役割と MAC/ARP を区別する。
- `ip route get`、`ss`、上限を設けた `tcpdump` キャプチャを読み、観測点を特定する。
- SSH の鍵認証とラボのファイアウォールポリシーを確認し、以前の状態に戻す。
- HTTP エラー、接続失敗、名前解決失敗を区別する。
- 管理経路と実験経路を分離し、自分が所有するファイル、VM、コンテナを特定する。

不足しているスキルを復習するには、[初級コースの総合演習](../beginner/08-container-cloud-capstone.md)を利用してください。ホストコマンドが使えない場合は、[ゲスト内のツールを準備する手順](../beginner/README.md#guest-tools)を完了してください。

## 専門分野を選ぶ {#tracks}

| 分野 | 優先する順序 | さらに学ぶ内容 |
|---|---|---|
| クラウドネットワーキング／SRE | 1 → 2 → 4 → 5 → 6 | CNI、DNS、ロードバランサー、ハイブリッド環境の境界をまたぐ性能と障害 |
| エンタープライズ／データセンター | 1 → 2 → 4 → 3 → 6 | Cisco の公式範囲を基に、残りの L2/L3、セキュリティ、仮想化、自動化のトピックを確認 |
| プロトコル／ネットワークソフトウェア | 1 → 2 → 4 → 6 | C/C++ の基礎を確立したうえで、トランスポート層とカーネル実装のプロジェクトに進む |

第 1、2、4 章は共通の前提です。データセンターの経路には第 3 章、クラウドには第 5 章を追加してください。プロトコル／Linux の経路では、第 4 章のホスト実験を、第 6 章の該当する評価に利用できます。選択した範囲の評価を完了してから、別の専門分野に進んでください。読書だけでなく、環境準備、失敗した試行、再現、報告の時間も確保してください。

## ラボの境界と所有権 {#lab-contract}

すべての章を、1 つの環境で順番に実行しないでください。

| 環境 | 準備と境界 | 完了前の確認 |
|---|---|---|
| ホストの観測 | 使い捨ての初級コース VM、インストール済みツール、自分が発生させるトラフィック | インターフェイス／プロセス／キャプチャの範囲、実行時間、自分のファイルのクリーンアップ |
| ルーティング／EVPN | 別の Linux ラボ VM、選択する netlab/provider のインストール／イメージ要件 | 上流の revision、ツール／イメージのバージョン、所有するラボ ID／リソース、復旧コマンド |
| クラウド | 使用が承認された既存のラボアカウント／クラスタと読み取り権限 | アカウント、リージョン、context、namespace、リソース所有者、コスト／権限／検証の範囲 |
| 設計／提供された証拠 | 必ずしも機器を用意せず、明示した前提と入力証拠を使う | 設計レビューと実トラフィックの検証を区別し、観測していない項目を明記する |

netlab/containerlab デバイスのアドレスや名前を、初級 VM の NIC に設定しないでください。一部の演習には、市販 NOS のイメージ、仮想化サポート、追加ボードが必要です。**各章と上流の前提条件を先に確認してください**。Docker 全体の prune、別のラボの teardown、本番環境への障害注入は、このコースの既定の手順ではありません。

すべての実験の前に次の記録を作成してください。バージョンと revision を記録するとは、実際に使った入力を記録することです。任意の組み合わせに互換性があるという保証ではありません。

| 記録項目 | 例 |
|---|---|
| 実験 ID と所有者 | 識別可能な ID と責任者のロール |
| 環境／権限 | ローカル VM、ラボコンテナ、または利用が承認されたクラウドの読み取り専用アクセス |
| トポロジー | ノード、インターフェイス、アドレス、VRF、観測経路、管理経路 |
| ツール／入力 | OS、カーネル、ツール、イメージのバージョン、上流の commit、入力ファイルのハッシュ |
| トラフィック範囲 | 送信元、宛先、プロトコル、ポート、最大実行時間 |
| ベースライン | 経路、ポリシー、サービスの状態、復旧用の構成 |
| 仮説／変更 | 予想される結果と変更対象を 1 つに絞る |
| 停止／復旧条件 | 管理機能の障害、想定外のリソース、復元、再確認 |

## 証拠の解釈 {#evidence-rules}

- **測定済み:** 明示した環境、時間範囲、トラフィックで観測した結果。
- **提供済み:** 他の人が収集した証拠。出所、範囲、元データとの関係を記録する。
- **説明用／合成:** 計算や validator の説明に使う入力。実トラフィックの成功として報告しない。
- **設計上の仮定:** テストされていない設計条件。未検証と明記したままにする。

観測がない場合は `unknown` とします。ルーティング出力が空であること、パケットが見つからないこと、`ping` がタイムアウトしたことだけでは、ポリシーによる拒否やエンドツーエンドの根本原因は証明できません。BGP セッションが確立していても、意図したプレフィックスや転送動作は証明されません。

## 最終ポートフォリオ {#portfolio}

自分の環境で、次の成果物を関連付けてください。

1. 1 件のリクエストの往路と復路、および各観測点。
2. 通常のトラフィックと、**禁止しなければならないトラフィック**の両方を示す証拠。
3. 1 つの障害またはポリシー変更について、変更前／実行中／変更後の記録。
4. 測定条件、得られていない証拠、採用しなかった仮説。
5. 範囲を絞った変更と復旧後の検証。
6. [最終評価](06-automation-capstone.md)の自動化結果と、人によるレビューで確認できる範囲。

元の証拠は利用が承認された場所に保管し、公開メモでは一貫した別名を使用してください。生パケット、ログ、アカウント、トポロジーのインベントリを無差別に公開しないでください。
