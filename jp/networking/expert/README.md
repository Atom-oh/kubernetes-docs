# エキスパート向けネットワーキング学習パス

> **リソース確認日**: 2026年9月15日
>
> **環境**: ホスト演習には、使い捨てのUbuntu Server 24.04 LTSまたはRocky Linux 9のVMを使用します。ルーティング／EVPNツールとクラウド環境には、それぞれ個別の章の前提条件があります。

この上級ワークブックは[初級コース](../beginner/README.md)に続くものです。プロトコルの原則をコードやパケットと結び付け、証拠に基づいてルーティングポリシー、Linuxのパフォーマンス、クラウド設計を評価します。

エキスパートレベルの目標は、**あるべき状態を定義し、観測結果で仮説を検証し、変更の影響と復旧方法を説明できること**です。一定期間学習したり、資格を取得したりするだけで、その能力が保証されるわけではありません。

## 受講前の確認 {#entry-check}

次の内容を説明し、再現できるようになったら、第1章に進んでください。

- IP、サブネット、ゲートウェイ、DNSの役割を、MAC／ARPの役割と区別する。
- `ip route get`、`ss`、範囲を限定した`tcpdump`キャプチャを読み、どの地点で観測したかを特定する。
- SSH鍵によるアクセスとラボのファイアウォールポリシーを確認し、以前の状態に戻す。
- HTTPエラー、接続失敗、名前解決失敗を区別する。
- スイッチ、ルーター、ファイアウォール、ロードバランサー、VLAN、LAN／WANの境界の役割を説明する。第7章に進む前に、[Network Fundamentals Part 5](../../basics/06-network-fundamentals-part5.md)でこの内容を確認する。
- 管理用の経路と実験用の経路を分け、自分が所有するファイル、VM、コンテナを特定する。

足りないスキルを復習するには、[初級コースの総合演習](../beginner/08-container-cloud-capstone.md)を使ってください。ホストでコマンドを実行できない場合は、[ゲストツールの準備](../beginner/README.md#guest-tools)を行ってください。

## 専門分野を選ぶ {#tracks}

| 方向性 | 優先順位 | さらに深く学ぶ内容 |
|---|---|---|
| クラウドネットワーキング／SRE | 1 → 2 → 4 → 5 → 6 | CNI、DNS、ロードバランサー、ハイブリッド境界をまたぐパフォーマンスと障害 |
| エンタープライズ／データセンター | 1 → 2 → 4 → 3 → 6 | 残るL2／L3、セキュリティ、仮想化、自動化のトピックをCiscoの公式範囲と照合する |
| プロトコル／ネットワークソフトウェア | 1 → 2 → 4 → 6 | C／C++の基礎を固めたうえで、トランスポートとカーネルの実装プロジェクトに取り組む |

第1、2、4章は共通の前提条件です。データセンター向けの経路では第3章を、クラウド向けの経路では第5章を追加してください。プロトコル／Linux向けの経路では、第4章のホスト実験を、第6章の対応する評価に利用できます。選んだ範囲の評価を完了してから、別の専門分野に取り組んでください。読解だけでなく、環境の準備、失敗した試行、再現、報告にも時間を割り当ててください。

## ラボの境界と所有権 {#lab-contract}

すべての章を、ひとつの環境で順番に実行しないでください。

| 環境 | 準備と境界 | 完了前の確認事項 |
|---|---|---|
| ホストの観測 | 初級コース用の使い捨てVM、インストール済みツール、自分が発生させたトラフィック | インターフェース／プロセス／キャプチャの範囲、実行時間、自分のファイルのクリーンアップ |
| ルーティング／EVPN | 独立したLinuxラボVMと、選択したnetlab／プロバイダーのインストール要件およびイメージ要件 | アップストリームのリビジョン、ツール／イメージのバージョン、自分が所有するラボID／リソース、復旧コマンド |
| クラウド | 承認済みの既存ラボアカウント／クラスターと読み取り権限 | アカウント、リージョン、コンテキスト、名前空間、リソース所有者、コスト／権限／検証の範囲 |
| 設計／提供された証拠 | 必ずしも機器を使わず、明示された前提と入力証拠を使用する | 設計レビューと実トラフィックの検証を区別し、未観測の項目に印を付ける |

netlab／containerlabのデバイスのアドレスや名前を、初級VMのNICにコピーしないでください。商用NOSイメージ、仮想化サポート、追加ボードが必要な演習もあります。**各章とアップストリームの前提条件を先に確認してください**。Dockerの全体的なprune、他のラボのteardown、本番環境への障害注入は、このコースの標準手順ではありません。

実験の前に、毎回この記録を作成してください。バージョンとリビジョンを記録するとは、実際の入力を記録することです。任意の組み合わせの互換性が保証されるわけではありません。

| 記録項目 | 記入例 |
|---|---|
| 実験IDと所有者 | 識別できるIDと担当する役割 |
| 環境／権限 | ローカルVM、ラボコンテナ、または承認済みクラウドの読み取り専用アクセス |
| トポロジー | ノード、インターフェース、アドレス、VRF、観測経路、管理経路 |
| ツール／入力 | OS、カーネル、ツール、イメージのバージョン、アップストリームのコミット、入力ファイルのハッシュ |
| トラフィックの範囲 | 送信元、宛先、プロトコル、ポート、最大実行時間 |
| ベースライン | 経路、ポリシー、サービスの状態、復旧用設定 |
| 仮説／変更 | 期待する結果と、変更する単一の項目 |
| 停止／復旧の基準 | 管理経路の障害、予期しないリソース、復元、再確認 |

## 証拠の解釈 {#evidence-rules}

- **測定済み:** 明示した環境、時間範囲、トラフィックで観測したもの。
- **提供済み:** 他者が収集したもの。出所、範囲、元の情報との関係を記録する。
- **説明用／合成データ:** 計算やバリデーターを説明する入力。実際のトラフィックが成功した証拠として報告しない。
- **設計上の前提:** 未検証の設計条件。未検証のまま明示しておく。

観測がないものは`unknown`です。ルーティング出力が空であること、パケットがないこと、`ping`がタイムアウトすることだけでは、ポリシーによる拒否やエンドツーエンドの根本原因は立証できません。BGPセッションが確立していても、意図したプレフィックスやフォワーディングの挙動が実現しているとは限りません。

## 最終ポートフォリオ {#portfolio}

自分の環境で、次の成果物を関連付けてください。

1. あるリクエストの往路と復路、および各観測地点。
2. 通常のトラフィックと、**禁止されなければならないトラフィック**の両方を示す証拠。
3. 1つの障害またはポリシー変更について、変更前／変更中／変更後の記録。
4. 測定条件、欠落している証拠、棄却した仮説。
5. 範囲を絞った変更と、復旧後の検証。
6. [最終評価](06-automation-capstone.md)の自動化結果と、人手によるレビューの限界。

元の証拠は承認済みの場所に保管し、公開メモでは一貫した別名を使ってください。パケット、ログ、アカウント、トポロジーの一覧を無差別に公開しないでください。
