# 주간 소식 다이제스트 — 2026년 28주차
> **마지막 업데이트**: 2026년 7월 11일

2026년 7월 4일 ~ 7월 11일 사이에 발표된 Kubernetes, Amazon EKS, CNCF 생태계 소식 중 이 문서와 관련 있는 항목을 정리했습니다.

## 이번 주 소식

### 1. etcd v3.7.0 릴리스

SIG etcd가 etcd v3.7.0을 릴리스했습니다. 오랫동안 요청되어 온 RangeStream 기능이 추가되었고, 레거시 v2store의 잔재가 완전히 제거되었으며, protobuf 전면 개편과 여러 성능 개선이 포함되었습니다.

- 원문: [Announcing etcd v3.7.0](https://kubernetes.io/blog/2026/07/08/announcing-etcd-3.7/) (Kubernetes 블로그, 2026-07-08)
- 관련 문서: [클러스터 아키텍처](../core/01-cluster-architecture.md)

### 2. ingress-nginx 은퇴 이후 마이그레이션 가이드

CNCF 블로그에 2026년 3월 ingress-nginx 컨트롤러 은퇴 이후의 마이그레이션 전략을 정리한 글이 올라왔습니다. 은퇴한 컨트롤러를 계속 사용하면 CVE 패치 중단 등 심각한 운영 리스크가 있으므로, Gateway API 기반 대안으로의 전환 계획이 필요합니다.

- 원문: [Navigating the ingress-NGINX retirement](https://www.cncf.io/blog/2026/07/09/navigating-the-ingress-nginx-retirement/) (CNCF 블로그, 2026-07-09)
- 관련 문서: [Gateway API](../networking/04-gateway-api.md), [AWS Load Balancer Controller](../networking/03-aws-lb-controller.md)

### 3. EKS Auto Mode, GPU 관리 요금 최대 60% 인하

2026년 7월 1일부터 EKS Auto Mode의 G 시리즈 관리 요금이 35%, P 시리즈와 AWS Trainium 요금이 60% 인하됩니다. 모든 EKS Auto Mode 클러스터에 자동 적용되며 별도 조치가 필요 없습니다.

- 원문: [Amazon EKS Auto Mode reduces GPU management fees by up to 60%](https://aws.amazon.com/about-aws/whats-new/2026/07/amazon-eks-auto-mode-gpu-price) (AWS What's New, 2026-07-07)
- 관련 문서: [EKS Auto Mode 비용 관리](../eks-auto-mode/06-cost-management.md)

### 4. Karpenter v1.14.0 릴리스

Karpenter AWS 프로바이더 v1.14.0이 릴리스되었습니다. CapacityBuffers API 지원, 프리뷰 인스턴스 타입 지원, 시작 템플릿의 EnclaveOptions 설정 등이 추가되었습니다.

- 원문: [karpenter-provider-aws v1.14.0](https://github.com/aws/karpenter-provider-aws/releases/tag/v1.14.0) (GitHub Releases, 2026-07-10)
- 관련 문서: [Karpenter](../autoscaling/02-karpenter.md)

### 5. Argo CD v3.4.5 릴리스

Argo CD 3.4 안정 버전의 패치 릴리스 v3.4.5가 공개되었습니다. 아울러 차기 마이너 버전인 v3.5.0-rc2도 테스트 중이므로, 운영 클러스터는 안정 채널의 패치를 따라가는 것이 좋습니다.

- 원문: [argo-cd v3.4.5](https://github.com/argoproj/argo-cd/releases/tag/v3.4.5) (GitHub Releases, 2026-07-09)
- 관련 문서: [ArgoCD](../gitops/argocd/README.md)

### 6. CloudWatch Application Signals, 오류·이상 징후·배포 이벤트 자동 캡처

CloudWatch Application Signals에 Service Events 기능이 추가되어 예외, 지연 시간 이상 징후, 배포 이벤트를 자동으로 캡처합니다. ADOT SDK 또는 CloudWatch Observability EKS 애드온으로 계측된 애플리케이션에서 바로 사용할 수 있습니다.

- 원문: [CloudWatch Application Signals now automatically captures errors, performance anomalies, and deployment events](https://aws.amazon.com/about-aws/whats-new/2026/06/cloudwatch-service-events/) (AWS What's New, 2026-07-06)
- 관련 문서: [CloudWatch Metrics](../observability/metrics/04-cloudwatch-metrics.md), [EKS 모니터링과 로깅](../eks/06-eks-monitoring-logging.md)

### 7. EMR on EKS, Apache Spark 트러블슈팅 에이전트 지원

Amazon EMR on EKS가 Apache Spark 워크로드용 AI 기반 트러블슈팅 에이전트를 지원합니다. EKS에서 Spark 작업 실패나 성능 문제를 진단하는 데 도움이 됩니다.

- 원문: [Amazon EMR on EKS now supports Apache Spark troubleshooting agent](https://aws.amazon.com/about-aws/whats-new/2026/07/amazon-emr-eks-spark-troubleshooting/) (AWS What's New, 2026-07-10)
- 관련 문서: [Data on EKS 개요](../data-on-eks/README.md)

### 8. AI 네이티브 워크로드를 위한 플랫폼 엔지니어링의 진화

CNCF 블로그에서 AI 네이티브 워크로드를 지원하기 위해 플랫폼 엔지니어링이 어떻게 진화해야 하는지 다뤘습니다. GPU 리소스 추상화, 모델 서빙 셀프서비스 등 내부 개발자 플랫폼(IDP)이 감당해야 할 새 요구 사항을 조망합니다.

- 원문: [Evolving platform engineering for AI-native workloads](https://www.cncf.io/blog/2026/07/06/evolving-platform-engineering-for-ai-native-workloads/) (CNCF 블로그, 2026-07-06)
- 관련 문서: [플랫폼 엔지니어링 개요](../platform-engineering/00-platform-engineering-overview.md)

### 9. AI 에이전트, 샌드박스만으로는 부족하다

CNCF 블로그에서 AI 에이전트 워크로드를 샌드박스에 격리하는 것만으로는 충분하지 않으며, 네트워크 정책·권한 최소화 등 다층 방어가 필요하다는 점을 짚었습니다. Kubernetes에서 에이전트 플랫폼을 운영할 때 참고할 만한 보안 관점입니다.

- 원문: [Why sandboxing your agent is not enough](https://www.cncf.io/blog/2026/07/07/why-sandboxing-your-agent-is-not-enough/) (CNCF 블로그, 2026-07-07)
- 관련 문서: [EKS 기반 Agentic AI 플랫폼](../ai-ml/03-agentic-ai-platform.md), [런타임 보안](../security/08-runtime-security.md)
