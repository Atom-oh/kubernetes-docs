# 네트워크 기초 Part 2 퀴즈 — 전송 계층과 TLS

> **마지막 업데이트**: 2026년 9월 11일

TCP·UDP·QUIC과 TLS에 대한 이해도를 테스트합니다.

## 객관식 문제

1. QUIC은 TCP의 스트림 간 HOL(Head-of-Line) 전달 의존성을 어떻게 피하나요?
   - A) 패킷 손실 시 전체 연결을 재수립한다
   - B) 하나의 연결에서 스트림마다 독립적인 바이트 순서를 유지한다
   - C) 순서 보장을 완전히 포기한다
   - D) 커널 레벨에서 재전송을 처리한다

<details>
<summary>정답 보기</summary>

**정답: B) 하나의 연결에서 스트림마다 독립적인 바이트 순서를 유지한다**

**설명:**
TCP는 누락 세그먼트 뒤의 바이트를 전달할 수 없어 여러 HTTP/2 스트림을 지연시킬 수 있습니다. QUIC은 다른 스트림에 도착한 데이터를 독립적으로 전달할 수 있습니다. 각 스트림의 누락 바이트 대기는 남고, 연결·경로의 혼잡 제어와 패킷 복구, 애플리케이션 의존성도 고려해야 합니다.

</details>

2. TLS 1.3에 대한 설명으로 옳지 않은 것은 무엇인가요?
   - A) 일반적인 전체 핸드셰이크는 약 1 RTT이고 조건을 충족한 재개에서 0-RTT 조기 데이터를 선택적으로 보낼 수 있다
   - B) RSA 키 교환과 취약한 암호 스위트가 제거됐다
   - C) TLS 1.3만으로 ECH 없이 SNI가 암호화된다
   - D) 임시 (EC)DHE는 전방 비밀성을 제공하지만 PSK 단독 교환과 0-RTT 데이터에는 예외가 있다

<details>
<summary>정답 보기</summary>

**정답: C) TLS 1.3만으로 ECH 없이 SNI가 암호화된다**

**설명:**
TLS 1.3만으로는 ClientHello SNI가 숨겨지지 않습니다. 지원·설정된 ECH(RFC 9849)는 내부 ClientHello를 보호합니다. TLS 1.3은 PSK 단독 키 교환도 허용하고 0-RTT 데이터에는 전방 비밀성이 없으므로, 전방 비밀성이 무조건 보장된다고 설명하면 틀립니다. 조기 데이터 전송도 핸드셰이크가 이미 완료되었다는 의미는 아닙니다.

</details>

3. BBR 혼잡 제어 방식의 특징은 무엇인가요?
   - A) 패킷 손실을 무시하고 항상 최대 속도로 전송하기 때문에
   - B) 병목 대역폭과 전파 RTT를 모델링해 전송을 조절하며 손실·ECN 처리 방식은 버전에 따라 다르다
   - C) 커널 대신 사용자 공간에서 동작하기 때문에
   - D) 재전송을 링크 계층에 위임하기 때문에

<details>
<summary>정답 보기</summary>

**정답: B) 병목 대역폭과 전파 RTT를 모델링해 전송을 조절하며 손실·ECN 처리 방식은 버전에 따라 다르다**

**설명:**
BBR은 손실에 따른 혼잡 윈도에만 의존하지 않고 대역폭·RTT 모델을 사용합니다. 손실 복구와 버전별 혼잡 반응도 필요합니다. 성능은 구현·경쟁 트래픽·경로 조건에 따라 달라지며 더 높은 처리량을 보장하지 않습니다.

</details>

4. TLS 1.3/QUIC의 0-RTT 세션 재개로 요청을 보낼 때 지켜야 하는 원칙은 무엇인가요?
   - A) 반드시 POST 요청만 보낸다
   - B) 0-RTT 데이터는 재생될 수 있으므로 애플리케이션이 재생 안전성을 명시적으로 평가한 작업만 허용한다
   - C) 0-RTT에서는 인증서 검증이 생략되므로 내부망에서만 쓴다
   - D) 0-RTT는 UDP에서만 동작하므로 TCP 폴백을 막는다

<details>
<summary>정답 보기</summary>

**정답: B) 0-RTT 데이터는 재생될 수 있으므로 애플리케이션이 재생 안전성을 명시적으로 평가한 작업만 허용한다**

**설명:**
조기 데이터 교환이 재생되면 애플리케이션이 같은 요청을 반복 처리할 수 있습니다. GET이라는 메서드 이름이나 멱등성 주장만으로 재생 안전성이 증명되지는 않습니다. 클라이언트·CDN·원본 서버 전체에서 승인된 작업으로 제한해야 합니다. HTTP 서버는 425 Too Early로 응답해 핸드셰이크 후 재시도하게 할 수 있습니다.

</details>
