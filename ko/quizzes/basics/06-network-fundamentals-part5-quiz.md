# 네트워크 기초 Part 5 퀴즈: 네트워크 장비, LAN과 WAN

> **마지막 업데이트**: 2026년 11월 19일

네트워크 장비의 포워딩 결정, VLAN·이중화, LAN 토폴로지, NAT, WAN과 클라우드 대응에 대한 이해도를 테스트합니다.

## 객관식 문제

1. 같은 VLAN 안의 L2 스위치와 서브넷 사이의 라우터가 프레임·패킷을 전달할 때 내리는 결정으로 옳은 것은 무엇인가요?
   - A) 스위치와 라우터 모두 목적지 IP로 최장 프리픽스 경로를 찾는다
   - B) 스위치는 목적지 MAC으로 MAC 테이블을 조회해 포트를 고르고, 라우터는 목적지 IP로 FIB를 조회해 TTL을 1 줄이고 L2 헤더를 새로 쓴다
   - C) 스위치는 TTL을 줄이고, 라우터는 출발지 MAC을 학습한다
   - D) 라우터는 IP 주소를 항상 자기 주소로 바꾼다

<details>
<summary>정답 보기</summary>

**정답: B) 스위치는 목적지 MAC으로 MAC 테이블을 조회해 포트를 고르고, 라우터는 목적지 IP로 FIB를 조회해 TTL을 1 줄이고 L2 헤더를 새로 쓴다**

**설명:**
L2 스위치는 출발지 MAC을 학습하고 목적지 MAC과 VLAN으로 포트를 고르며 프레임 내용을 바꾸지 않습니다. 라우터는 최장 프리픽스 경로의 다음 홉으로 보내면서 TTL을 줄이고 출발지·목적지 MAC을 새로 씁니다. NAT가 없다면 IP 주소는 그대로이므로 D는 틀렸습니다.

</details>

2. 스위치 두 대가 802.1Q 트렁크로 연결되어 있고, 두 스위치 모두 VLAN 10과 VLAN 20에 포트가 있습니다. 라우터 한 대가 두 VLAN 사이를 라우팅합니다. 브로드캐스트 영역은 몇 개인가요?
   - A) 1개
   - B) 2개
   - C) 4개
   - D) 스위치 포트 수만큼

<details>
<summary>정답 보기</summary>

**정답: B) 2개**

**설명:**
VLAN 하나가 브로드캐스트 영역 하나이며, 같은 VLAN이 트렁크로 여러 스위치에 걸쳐 있어도 하나의 브로드캐스트 영역입니다. 라우터는 L2 브로드캐스트로 받은 패킷을 다른 인터페이스로 넘기지 않으므로(RFC 1812 §5.3.4) VLAN 10과 VLAN 20, 두 개입니다. 스위치 포트 수만큼 나뉘는 것은 충돌 영역입니다.

</details>

3. 802.1Q 트렁크의 네이티브 VLAN에 대한 설명으로 옳은 것은 무엇인가요?
   - A) 네이티브 VLAN 프레임은 항상 VID 4095 태그를 단다
   - B) 트렁크 양쪽의 네이티브 VLAN은 달라도 문제가 없다
   - C) 태그 없이 오가는 VLAN이며, Cisco Catalyst 기본값은 VLAN 1이고 양쪽 설정이 같아야 한다
   - D) 네이티브 VLAN은 액세스 포트에서만 쓰는 개념이다

<details>
<summary>정답 보기</summary>

**정답: C) 태그 없이 오가는 VLAN이며, Cisco Catalyst 기본값은 VLAN 1이고 양쪽 설정이 같아야 한다**

**설명:**
장비는 트렁크로 받은 태그 없는 프레임을 네이티브 VLAN에 넣고 네이티브 VLAN 프레임은 태그 없이 보냅니다. 양쪽이 다르면 한쪽 VLAN의 프레임이 다른 VLAN으로 들어가 분리가 깨지고 스패닝 트리 루프가 생길 수 있습니다. VID 0과 4095는 예약값이라 VLAN에 쓰지 않습니다.

</details>

4. 스패닝 트리 프로토콜(STP)이 필요한 근본 이유와 루트 브리지 선출 기준으로 옳은 것은 무엇인가요?
   - A) Ethernet 헤더에 TTL이 없어 L2 루프의 프레임이 사라지지 않으므로 일부 포트를 차단하며, 브리지 ID(우선순위 + MAC)가 가장 낮은 스위치가 루트가 된다
   - B) IP 패킷의 TTL을 늘리기 위해서이며, 포트 수가 가장 많은 스위치가 루트가 된다
   - C) 링크 대역폭을 합치기 위해서이며, MAC이 가장 높은 스위치가 루트가 된다
   - D) VLAN 간 라우팅을 위해서이며, 우선순위가 가장 높은 값인 스위치가 루트가 된다

<details>
<summary>정답 보기</summary>

**정답: A) Ethernet 헤더에 TTL이 없어 L2 루프의 프레임이 사라지지 않으므로 일부 포트를 차단하며, 브리지 ID(우선순위 + MAC)가 가장 낮은 스위치가 루트가 된다**

**설명:**
루프가 있으면 브로드캐스트가 계속 돌며 복제되고 MAC 테이블이 흔들립니다. STP는 이중 링크 일부를 차단해 트리를 만듭니다. 기본 우선순위는 32768이므로 설정하지 않으면 MAC이 가장 낮은 스위치가 루트가 되며, 실무에서는 코어·분배 스위치의 우선순위를 낮춰 루트를 고정합니다. 대역폭을 합치는 것은 LACP의 역할입니다.

</details>

5. 10Gbps 링크 4개를 LACP로 묶은 LAG에서 TCP 연결 하나가 낼 수 있는 최대 처리량에 대한 설명으로 옳은 것은 무엇인가요?
   - A) 40Gbps: LAG는 패킷 단위로 모든 링크에 고르게 나눈다
   - B) 10Gbps 이하: 해시로 같은 흐름은 항상 같은 멤버 링크로 간다
   - C) 20Gbps: 송신과 수신을 서로 다른 링크로 보낸다
   - D) STP가 링크 3개를 차단하므로 LAG와 무관하게 10Gbps다

<details>
<summary>정답 보기</summary>

**정답: B) 10Gbps 이하: 해시로 같은 흐름은 항상 같은 멤버 링크로 간다**

**설명:**
링크 집선은 주소·포트 같은 값을 해시해 프레임을 멤버 링크 하나에 배정하므로 흐름 하나는 링크 하나에 머뭅니다. 합계 40Gbps는 흐름이 많을 때만 쓸 수 있습니다. STP는 LAG를 링크 하나로 보므로 멤버 링크를 차단하지 않습니다.

</details>

6. VRRPv3에서 백업 라우터의 우선순위가 100이고 광고 간격이 기본값 1초일 때, Active 라우터가 멈춘 뒤 백업이 넘겨받기까지 걸리는 시간에 가장 가까운 값은 무엇인가요?
   - A) 약 1초
   - B) 약 3.61초
   - C) 약 10초
   - D) 약 30초

<details>
<summary>정답 보기</summary>

**정답: B) 약 3.61초**

**설명:**
`Active_Down_Interval = 3 × 광고 간격 + Skew_Time`이고 `Skew_Time = ((256 − 우선순위) × 광고 간격) / 256`입니다. (256 − 100) / 256 ≈ 0.61초이므로 3 + 0.61 ≈ 3.61초입니다. 10초는 HSRP의 기본 hold 시간, 30초는 802.1D STP의 listening·learning 시간입니다.

</details>

7. Pod 수천 개가 AWS NAT 게이트웨이(공인 IPv4 1개) 하나를 거쳐 같은 외부 API(같은 IP:443)를 호출하다가 새 연결이 실패합니다. 원인과 대응으로 가장 적절한 것은 무엇인가요?
   - A) NAT 게이트웨이의 보안 그룹을 넓힌다
   - B) 공인 IP 하나당 고유 목적지당 55,000개 동시 연결 한도에 닿았을 수 있으므로 `ErrorPortAllocation`을 확인하고, 연결 재사용·보조 IP 추가·NAT 게이트웨이 분산을 검토한다
   - C) NAT 게이트웨이는 연결 수 제한이 없으므로 외부 API 장애다
   - D) NACL에서 포트 443을 거부한다

<details>
<summary>정답 보기</summary>

**정답: B) 공인 IP 하나당 고유 목적지당 55,000개 동시 연결 한도에 닿았을 수 있으므로 `ErrorPortAllocation`을 확인하고, 연결 재사용·보조 IP 추가·NAT 게이트웨이 분산을 검토한다**

**설명:**
고유 목적지는 목적지 IP·포트·프로토콜 조합이므로 같은 API 하나로 몰리면 한도에 먼저 닿습니다. IPv4 주소는 최대 8개까지 연결할 수 있고, 포트를 배정하지 못하면 `ErrorPortAllocation`이 0보다 커집니다. NAT 게이트웨이에는 보안 그룹을 연결할 수 없으므로 A는 틀렸습니다.

</details>

8. 통신사가 CGNAT와 가입자 장비(CPE) 사이 구간에 쓰도록 할당된 주소 대역과 그 성격으로 옳은 것은 무엇인가요?
   - A) `172.16.0.0/12`: RFC 1918 사설 대역
   - B) `169.254.0.0/16`: 링크 로컬 대역
   - C) `100.64.0.0/10`: RFC 6598 공유 주소 공간이며 RFC 1918과 별개
   - D) `203.0.113.0/24`: CGNAT 전용 공인 대역

<details>
<summary>정답 보기</summary>

**정답: C) `100.64.0.0/10`: RFC 6598 공유 주소 공간이며 RFC 1918과 별개**

**설명:**
RFC 6598은 CGN 배치를 위해 `100.64.0.0/10`을 할당했습니다. 가입자 내부망이 RFC 1918을 써도 겹치지 않게 하려는 목적이며, 이 대역의 패킷과 경로는 통신사 경계를 넘지 않아야 합니다. `203.0.113.0/24`는 RFC 5737의 문서용 예제 대역입니다.

</details>

9. 서브넷의 인스턴스가 외부 HTTPS API를 호출하는데, 보안 그룹은 아웃바운드 443을 허용하고 커스텀 NACL은 아웃바운드 443만 허용하며 인바운드는 기본 거부입니다. 응답이 돌아오지 않는 이유로 옳은 것은 무엇인가요?
   - A) 보안 그룹은 상태 비저장이라 인바운드 443을 따로 허용해야 한다
   - B) NACL은 상태 비저장이라 응답이 돌아오는 임시 포트(예: Linux 32768–61000)를 인바운드에 허용해야 한다
   - C) NACL은 모든 규칙을 평가한 뒤 허용 규칙만 적용한다
   - D) 보안 그룹은 거부 규칙이 우선한다

<details>
<summary>정답 보기</summary>

**정답: B) NACL은 상태 비저장이라 응답이 돌아오는 임시 포트(예: Linux 32768–61000)를 인바운드에 허용해야 한다**

**설명:**
보안 그룹은 상태 저장이라 응답을 자동 허용하고 허용 규칙만 가집니다. NACL은 서브넷 수준의 상태 비저장 필터로, 허용·거부 규칙을 번호 오름차순으로 평가해 처음 일치한 규칙을 적용하며 응답 트래픽도 명시적으로 허용해야 합니다.

</details>

10. 모든 leaf가 모든 spine에 연결되고 leaf끼리는 직접 연결되지 않는 2계층 spine-leaf 패브릭에서, 서로 다른 leaf에 붙은 두 서버 사이 트래픽이 거치는 스위치 경로는 무엇인가요?
    - A) leaf → leaf
    - B) leaf → spine → leaf (스위치 3대, 스위치 간 링크 2개)
    - C) leaf → spine → spine → leaf
    - D) 서버 위치에 따라 달라 예측할 수 없다

<details>
<summary>정답 보기</summary>

**정답: B) leaf → spine → leaf (스위치 3대, 스위치 간 링크 2개)**

**설명:**
leaf끼리, spine끼리 직접 연결하지 않으므로 다른 leaf로 가는 트래픽은 항상 spine 하나를 거칩니다. 어느 서버 쌍이든 거리가 같아 지연이 예측 가능하고, ECMP로 모든 spine 경로를 함께 씁니다.

</details>

11. 두 고객이 같은 사설 대역 `10.0.0.0/16`을 쓰는데도 통신사 MPLS L3VPN 안에서 경로가 섞이지 않는 이유로 옳은 것은 무엇인가요?
    - A) 통신사가 고객 주소를 CGNAT로 바꾸기 때문이다
    - B) PE 라우터가 고객 연결을 별도의 VRF에 묶고, 고객 경로에 Route Distinguisher를 붙여 구분하기 때문이다
    - C) SD-WAN 컨트롤러가 중복 주소를 막기 때문이다
    - D) 전용회선이라 다른 고객과 물리적으로 분리되기 때문이다

<details>
<summary>정답 보기</summary>

**정답: B) PE 라우터가 고객 연결을 별도의 VRF에 묶고, 고객 경로에 Route Distinguisher를 붙여 구분하기 때문이다**

**설명:**
RFC 4364의 BGP/MPLS IP VPN에서 PE 라우터는 고객 연결을 VRF라는 별도 라우팅 테이블에 묶고, BGP로 나르는 고객 경로에 Route Distinguisher를 붙여 VPN-IPv4 주소로 구분합니다. 그래서 고객 간 사설 주소가 겹쳐도 섞이지 않습니다. SD-WAN은 회선 위의 오버레이 서비스 모델이고, 전용회선은 점대점 회선이라 MPLS L3VPN과 다른 서비스입니다.

</details>
