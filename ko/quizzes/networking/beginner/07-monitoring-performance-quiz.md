# 관측과 성능 퀴즈

[학습 문서](../../../networking/beginner/07-monitoring-performance.md)

6문항입니다. 정답뿐 아니라 해설을 자신의 말로 설명하세요.

1. LISTEN 소켓에서 Recv-Q가 3, Send-Q가 128입니다. 올바른 해석은?

   - A) 수신 본문 3바이트, 송신 본문 128바이트
   - B) accept를 기다리는 연결 3개, 최대 accept backlog 128
   - C) 재전송 3회, RTT 128ms
   - D) 현재 연결 총 128개

<details>
<summary>정답 보기</summary>

**정답: B) accept를 기다리는 연결 3개, 최대 accept backlog 128**

**설명:** LISTEN 큐는 연결 수입니다. ESTABLISHED 소켓의 스트림 바이트와 단위가 다르므로 상태부터 읽어야 합니다.

</details>

2. IP 주소로 실행한 curl에서 time_namelookup이 매우 작습니다. 무엇을 결론 낼 수 있나요?

   - A) 조직 DNS가 항상 빠르다
   - B) 모든 DNS 캐시가 비어 있다
   - C) 이 요청은 DNS 성능 검증에 적합하지 않다
   - D) 서버의 처리 시간이 0이다

<details>
<summary>정답 보기</summary>

**정답: C) 이 요청은 DNS 성능 검증에 적합하지 않다**

**설명:** IP 리터럴 요청은 서비스 이름의 DNS 조회를 시험하지 않습니다. 누적 시간 필드를 독립적인 구간으로 더하는 것도 피합니다.

</details>

3. curl은 성공하지만 tcpdump 캡처가 비어 있습니다. 먼저 확인할 것은?

   - A) 선택한 NIC·필터·캡처 시간대
   - B) 모든 호스트의 라우팅 테이블 초기화
   - C) SSH 비밀번호 로그인 허용
   - D) TCP 버퍼 최댓값 증가

<details>
<summary>정답 보기</summary>

**정답: A) 선택한 NIC·필터·캡처 시간대**

**설명:** 캡처는 관측 위치와 조건에 종속됩니다. 클라이언트 요청 시각과 캡처 시각을 맞추고 실습 NIC를 선택했는지 확인합니다.

</details>

4. 100 Mbit/s와 100 MB/s의 관계는?

   - A) 항상 동일하다
   - B) Mbit/s가 8배 크다
   - C) HTTP에서만 동일하다
   - D) 100 MB/s는 800 Mbit/s에 해당하는 양의 비율이다

<details>
<summary>정답 보기</summary>

**정답: D) 100 MB/s는 800 Mbit/s에 해당하는 양의 비율이다**

**설명:** 1 byte는 8 bits입니다. 실제 애플리케이션 처리량 비교에는 프로토콜 오버헤드·측정 지점·실행 조건도 필요합니다.

</details>

5. 한 번 관측한 Send-Q가 0보다 큽니다. 적절한 다음 행동은?

   - A) 네트워크 손실로 확정한다
   - B) 모든 sysctl 버퍼 값을 두 배로 바꾼다
   - C) 상태·시간 변화·앱 진행·패킷을 대조한다
   - D) 원격 서버의 방화벽을 끈다

<details>
<summary>정답 보기</summary>

**정답: C) 상태·시간 변화·앱 진행·패킷을 대조한다**

**설명:** Send-Q에는 아직 확인 응답되지 않은 바이트와 미전송 데이터가 포함될 수 있습니다. 단일 스냅샷은 원인의 증명이 아닙니다.

</details>

6. 블록 I/O 스케줄러와 네트워크 qdisc를 바르게 구분한 것은?

   - A) 각각 저장장치 요청과 네트워크 송신 큐를 다룬다
   - B) 둘 다 DNS 캐시이다
   - C) 둘 다 SSH 키를 검증한다
   - D) 둘 다 동일한 sysctl 하나로 설정한다

<details>
<summary>정답 보기</summary>

**정답: A) 각각 저장장치 요청과 네트워크 송신 큐를 다룬다**

**설명:** 관측한 병목이 어느 경로에 있는지 먼저 확인합니다. 이름에 스케줄러가 들어간다고 같은 자원이나 튜닝 효과를 가진 것은 아닙니다.

</details>
