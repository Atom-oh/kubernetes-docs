# 퀴즈 2. 주소, 서브넷, 인터페이스

> **지원 버전**: Ubuntu Server 24.04 LTS(기본), Rocky Linux 9(대안)
> **마지막 업데이트**: 2026년 9월 15일

[본문으로](../../../networking/beginner/02-addressing-interfaces.md) | [과정 준비](../../../networking/beginner/README.md)

격리된 두 VM 실습 조건을 기준으로 해설을 열기 전에 답을 고르세요. 예시는 해석 대상이며 호스트 설정 변경 지시가 아닙니다.

1. 클라이언트가 서버 `192.0.2.20:8080`으로 HTTP 요청을 직접 보냅니다. 올바른 설명은 무엇인가요?

   - A) `8080`은 서버의 MAC 주소입니다.
   - B) Ethernet은 로컬 링크의 MAC, IP는 라우팅할 주소를 사용하고 TCP `8080`은 서비스가 대기해야 하는 전송 끝점입니다.
   - C) 서버 IP를 할당하면 HTTP가 자동 시작됩니다.
   - D) TCP와 UDP의 `8080`은 항상 같은 프로그램에 도달합니다.

<details>
<summary>정답 보기</summary>

**정답: B**

**설명:** 로컬 Ethernet 프레임이 IP 패킷을 담고 그 안에 전송 정보와 애플리케이션 데이터가 있습니다. 포트는 케이블이 아니라 프로토콜별 번호입니다. 주소 설정만으로 리스너가 생기지 않습니다. ICMP echo 성공도 TCP `8080`이 열렸다는 증거가 아닙니다.

</details>

2. `192.0.2.10/24`의 네트워크, 브로드캐스트, 일반 호스트 범위는 무엇인가요?

   - A) 네트워크 `.10`, 브로드캐스트 `.24`, 호스트 `.1`–`.9`.
   - B) 네트워크 `192.0.2.0`, 브로드캐스트 `192.0.2.255`, 호스트 `.1`–`.254`.
   - C) 네트워크 `192.0.0.0`, 브로드캐스트 `192.0.255.255`, 호스트 `.0`–`.255`.
   - D) 실습의 256개 주소 모두 일반 호스트 주소입니다.

<details>
<summary>정답 보기</summary>

**정답: B**

**설명:** `/24`는 네트워크 24비트를 남겨 호스트 비트가 8개, 주소가 256개입니다. 이번 일반 서브넷에서는 호스트 비트가 모두 0인 주소와 모두 1인 주소를 네트워크·브로드캐스트에 사용하므로 호스트용 254개가 남습니다. `/31`, `/32`의 특별한 용도에 이 계산을 억지로 적용하면 안 됩니다.

</details>

3. `192.0.2.70/26`과 같은 서브넷인 목적지와 이유는 무엇인가요?

   - A) `.130`. 첫 세 옥텟이 같기 때문입니다.
   - B) `.100`. `.64/26` 블록이 `.64`–`.127`이며 호스트 범위는 `.65`–`.126`이기 때문입니다.
   - C) `.20`. 문서용 주소는 모두 로컬이기 때문입니다.
   - D) `.127`. 브로드캐스트 주소가 권장 서버 주소이기 때문입니다.

<details>
<summary>정답 보기</summary>

**정답: B**

**설명:** `/26`은 호스트 비트 6개, 한 블록에 64개 주소를 남깁니다. 시작점은 `.0`, `.64`, `.128`, `.192`입니다. `.70`과 `.100`은 두 번째 블록이고 `.130`은 세 번째입니다. 모든 네트워크가 `/24`라고 가정하지 말고 실제 접두사를 비교합니다.

</details>

4. 클라이언트에 관리 기본 경로와 실습 NIC의 `192.0.2.0/24` 연결 경로가 있습니다. `.20` 패킷은 어디로 가야 하나요?

   - A) default가 항상 우선이므로 관리 기본 경로로 갑니다.
   - B) `/24`가 `/0`보다 긴 일치 접두사이므로 실습 NIC로 직접 갑니다.
   - C) `.1`은 자동 게이트웨이이므로 그쪽으로 갑니다.
   - D) 실습 NIC에 DNS를 설정하기 전에는 보낼 수 없습니다.

<details>
<summary>정답 보기</summary>

**정답: B**

**설명:** 연결 경로가 더 구체적입니다. 같은 서브넷에서 숫자 IP로 통신할 때 실습 게이트웨이나 DNS는 필요하지 않습니다. 기존 관리 기본 경로를 보존하세요. 게이트웨이는 실제로 존재하고 접근 가능해야 하며 `.1`이라는 주소만으로 라우터가 되지 않습니다.

</details>

5. 역할을 올바르게 연결한 것은 무엇인가요?

   - A) DHCP는 모든 패킷 전달, DNS는 클라이언트 MAC 할당, ARP는 이름 해석입니다.
   - B) DHCP는 주소·설정 임대, DNS는 이름 레코드 질의 응답, ARP는 링크의 IPv4 다음 홉 이웃을 MAC으로 해석합니다.
   - C) DNS 성공은 모든 서비스 도달을 증명합니다.
   - D) ARP는 인터넷 어디에 있는 서버의 MAC도 찾습니다.

<details>
<summary>정답 보기</summary>

**정답: B**

**설명:** 라우터로 가는 원격 IPv4 목적지라면 ARP는 보통 원격 서버가 아니라 로컬 링크 라우터의 MAC을 찾습니다. DHCP는 설정 교환, DNS는 이름 해석입니다. 서로 다른 질문에 답하므로 독립적으로 성공하거나 실패할 수 있습니다.

</details>

6. 주소를 추가하기 전에 실습 NIC를 확실히 식별하는 증거는 무엇인가요?

   - A) 항상 `eth1`입니다.
   - B) `ip a`에서 루프백을 제외한 두 번째 행입니다.
   - C) MAC 전체가 하이퍼바이저에서 내부 전용 네트워크에 연결된 것으로 기록한 NIC와 같습니다.
   - D) 이미 기본 경로를 가진 NIC입니다.

<details>
<summary>정답 보기</summary>

**정답: C**

**설명:** 게스트 이름과 순서는 달라집니다. 각 VM의 관리·실습 MAC을 따로 기록하고 `ip -br link`와 대조하세요. 기본 경로는 보통 건드리면 안 되는 관리 경로를 가리킵니다. 실습 NIC는 이번 주소 추가 전에 기존 IPv4가 없어야 한다는 조건도 만족해야 합니다.

</details>

7. `ip a`의 동작과 `LOWER_UP` 없는 `UP`의 의미로 맞는 것은 무엇인가요?

   - A) `ip a`는 주소를 추가하고 `UP`은 인터넷 접근을 증명합니다.
   - B) `ip a`는 주소를 나열하며 관리상 켜진 링크에도 하위 계층 캐리어가 없을 수 있습니다.
   - C) 두 표현 모두 DNS 성공을 뜻합니다.
   - D) 루프백의 `UNKNOWN`은 항상 게스트 고장입니다.

<details>
<summary>정답 보기</summary>

**정답: B**

**설명:** `a`는 address 대상의 줄임말이며 추가에는 `add` 동작이 필요합니다. 관리상 활성화, 캐리어, 주소, 경로, 서비스 도달은 별개 관찰입니다. 캐리어가 없으면 IP 설정 변경보다 먼저 가상 케이블과 네트워크 연결을 확인합니다.

</details>

8. `ip -4 route get 192.0.2.20`은 실습 NIC와 출발지 `.10`을 선택하지만 ping 응답은 없습니다. 경로 조회로 증명한 것은 무엇인가요?

   - A) 상대가 패킷을 받았습니다.
   - B) 커널이 그 경로·출발지를 선택한다는 뜻이며 조회 자체는 시험 패킷을 보내지 않았습니다.
   - C) 방화벽이 ICMP와 TCP를 허용합니다.
   - D) ARP가 반드시 상대를 찾았습니다.

<details>
<summary>정답 보기</summary>

**정답: B**

**설명:** 경로 선택은 로컬 증거입니다. 제한된 ping 이후 이웃을 확인하면 로컬 링크 해석 실패와 MAC은 해석됐지만 ICMP가 필터링될 수 있는 상황을 나눌 수 있습니다. 라우팅 결정을 끝간 통신 성공으로 여기거나 증상을 숨기려고 방화벽을 끄지 마세요.

</details>

9. 트래픽 이후 이웃 항목에 예상한 상대 MAC과 `STALE` 상태가 있습니다. 무슨 뜻인가요?

   - A) 인터페이스를 영구적으로 사용할 수 없습니다.
   - B) 캐시 매핑이 있고 사용 시 재확인이 필요합니다. 곧바로 장애라는 뜻은 아닙니다.
   - C) 누군가 반드시 상대를 사칭했습니다.
   - D) 모든 이웃 항목을 flush해야 합니다.

<details>
<summary>정답 보기</summary>

**정답: B**

**설명:** 이웃 상태는 도달 확인에 따라 바뀝니다. `REACHABLE`은 최근 확인, `INCOMPLETE`는 해석 중, `FAILED`는 해석 실패입니다. 트래픽 전 빈 테이블은 정상일 수 있습니다. 모든 캐시가 항상 `REACHABLE`이어야 한다고 요구하지 말고 MAC 기록과 트래픽 관찰을 함께 사용하세요.

</details>

10. 수동 추가 주소에 `valid_lft forever`가 나옵니다. 재부팅 후 유지되나요? 정리할 대상은 무엇인가요?

   - A) 유지됩니다. 게스트 주소 테이블 전체를 지워야 합니다.
   - B) 영구성을 뜻하지 않습니다. 식별한 실습 NIC에서 추가에 성공한 정확한 IP·접두사만 지우고 원래 down일 때만 down으로 복원합니다.
   - C) 유지됩니다. Linux 재설치로만 지울 수 있습니다.
   - D) 관리 기본 경로부터 지웁니다.

<details>
<summary>정답 보기</summary>

**정답: B**

**설명:** `forever`는 런타임 만료 타이머가 없다는 뜻이지 저장된 설정이 아닙니다. 처음 IPv4가 없다는 실습 조건에서 유일한 실습 IPv4를 지우면 자동 연결 경로도 제거됩니다. 재부팅이나 관리자가 이미 제거했다면 없음을 확인하고 삭제를 건너뜁니다. 변수와 원래 상태를 추측하지 말고 기록으로 복구합니다.

</details>

11. 실습 NIC에 `fe80:`으로 시작하는 IPv6 주소가 보입니다. 적절한 대응은 무엇인가요?

   - A) IPv4를 작동시키기 위해 IPv6를 전역 비활성화합니다.
   - B) 링크 로컬일 가능성을 이해하고 기존 IPv6를 그대로 둔 채 IPv4 실습을 진행합니다.
   - C) 모든 IPv6 주소는 전역이므로 인터넷 접근을 가정합니다.
   - D) 그 주소에 IPv4 ARP 항목을 설정합니다.

<details>
<summary>정답 보기</summary>

**정답: B**

**설명:** IPv6 주소는 128비트입니다. 링크 로컬 범위는 해당 링크에 제한되며 목적지로 사용할 때 인터페이스 영역 지정이 필요할 수 있습니다. IPv6는 ARP 대신 이웃 탐색을 사용하며 IPv4식 브로드캐스트가 없습니다. 링크 로컬 주소 하나만으로 인터넷 도달을 증명하지 못합니다.

</details>

12. 정직하고 충분한 완료 설명은 무엇인가요?

   - A) “명령을 읽었으므로 예시를 실환경 검증했습니다.”
   - B) “실습 주소가 있으므로 모든 TCP 서비스가 작동합니다.”
   - C) “MAC으로 두 NIC를 확인하고 주소·경로와 제한된 통신 증거를 확인했으며 관리를 유지하고 내 주소만 제거한 뒤 기록한 링크 상태로 복원했습니다.”
   - D) “호스트 전용 네트워크는 항상 격리되어 있고 DHCP가 없습니다.”

<details>
<summary>정답 보기</summary>

**정답: C**

**설명:** 실습 계약에는 설정, 증거, 복구가 모두 포함됩니다. 내부 전용 실습망에는 DHCP·업링크가 없으며 호스트 전용 기본값이 같다고 가정하면 안 됩니다. 본문 예시는 설명용이지 실제 시험 기록이 아닙니다. 다음 장은 남은 변수에 의존하지 않고 영구 설정을 수행합니다.

</details>
