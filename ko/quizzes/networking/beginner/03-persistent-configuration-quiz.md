# 영구 네트워크 설정 퀴즈

> **마지막 업데이트**: 2026년 9월 15일

[본문](../../../networking/beginner/03-persistent-configuration.md)을 참고하여 정답 문자뿐 아니라 이유도 설명해 보세요. 실습은 `192.0.2.0/24`의 클라이언트 `.10/24`·서버 `.20/24`이며 내부망에 DHCP·라우터·DNS는 없습니다. 별도의 관리 NIC는 변경하지 않습니다.

## 문제

1. VM의 두 인터페이스 이름이 낯섭니다. 어느 NIC에 `192.0.2.10/24`를 설정해야 할까요?
   - A) `ip` 목록의 첫 인터페이스
   - B) 현재 기본 경로가 있는 인터페이스
   - C) 하이퍼바이저에 기록한 내부 실습 어댑터의 MAC과 일치하는 인터페이스
   - D) 현재 UP으로 표시된 아무 인터페이스

<details>
<summary>정답 보기</summary>

**정답: C) 하이퍼바이저에 기록한 내부 실습 어댑터의 MAC과 일치하는 인터페이스**

**설명:** 이름과 목록 순서로 역할을 정할 수 없습니다. 기록한 MAC을 `ip -br link`와 대조한 뒤 주소·경로를 확인합니다. 더 익숙한 이름을 가진 NIC라도 관리 NIC라면 보존해야 합니다.

</details>

2. `systemd-networkd`가 실행 중이지만 실습 NIC의 Netplan 정의는 NetworkManager를 선택합니다. 올바른 행동은 무엇인가요?
   - A) 실행 중인 networkd가 모든 NIC를 소유한다고 판단
   - B) 일치하는 Netplan 정의와 생성된 프로필을 조사한 뒤 편집할 소유자를 결정
   - C) 같은 NIC의 `.network` 파일도 추가
   - D) 두 서비스를 끄고 `ip address add`만 사용

<details>
<summary>정답 보기</summary>

**정답: B) 일치하는 Netplan 정의와 생성된 프로필을 조사한 뒤 편집할 소유자를 결정**

**설명:** 서비스 실행 상태와 장치별 소유권은 다릅니다. Netplan이 백엔드 설정을 만들 수 있고 직접 추가한 경쟁 정의는 충돌할 수 있습니다. `ip` 명령만으로는 실행 상태만 바뀌며 영구 부팅 지시가 저장되지 않습니다.

</details>

3. 앞 Netplan 파일에 실습 NIC의 DNS 목록이 있습니다. 뒤 파일의 `nameservers: {addresses: []}`로 기존 목록을 안전하게 지울 수 있을까요?
   - A) 그렇다. 번호가 큰 파일은 모든 이전 값을 항상 삭제한다
   - B) 그렇다. 목록은 항상 단일 값처럼 처리된다
   - C) 아니다. 대신 Netplan 파일 전체를 옮겨야 한다
   - D) 아니다. 목록은 이어 붙을 수 있으므로 병합 결과와 소유 정의를 조사해야 한다

<details>
<summary>정답 보기</summary>

**정답: D) 아니다. 목록은 이어 붙을 수 있으므로 병합 결과와 소유 정의를 조사해야 한다**

**설명:** 뒤 overlay가 보편적인 초기화 수단은 아닙니다. `netplan get`, 입력 파일, 일치하는 ID·MAC, 프로비저닝 원본을 확인하세요. 백업 후 확인한 실습 소유 정의를 수정하거나 기존 정의 없는 새 NIC 경로를 사용합니다. 실습 충돌을 풀려고 관리 설정을 교체하지 않습니다.

</details>

4. 과정의 클라이언트 실습 NIC에 맞는 영구 IPv4 설정은 무엇인가요?
   - A) `192.0.2.10/24`, 해당 NIC의 게이트웨이·DNS 없음, DHCP 비활성
   - B) `192.0.2.10/24`, 모든 서브넷에는 `.1` 라우터가 있으므로 게이트웨이 `192.0.2.1`
   - C) DHCP와 공개 DNS를 켜면 주소 임대가 생김
   - D) 서버와 같은 `192.0.2.20/24`

<details>
<summary>정답 보기</summary>

**정답: A) `192.0.2.10/24`, 해당 NIC의 게이트웨이·DNS 없음, DHCP 비활성**

**설명:** 상대는 같은 `/24`에 직접 연결됩니다. 내부망에는 라우터·DHCP·DNS가 없습니다. 추측한 게이트웨이는 라우터를 만들지 않고 DNS는 DHCP 임대를 제공하지 않습니다. 별도 관리 연결은 자기 설정을 유지합니다.

</details>

5. `netplan generate`는 성공했고 미승인 `netplan try`의 시간이 만료됐습니다. 무엇이 타당한가요?
   - A) 문법 검증 성공으로 MAC·관리 경로도 올바름이 증명됨
   - B) 시간 만료는 디스크와 실행 상태의 완전한 복구를 보장함
   - C) 콘솔에서 실행 상태·디스크를 확인하고 필요하면 정확한 파일의 복구 절차 수행
   - D) 파일을 읽지 않고 바로 재부팅

<details>
<summary>정답 보기</summary>

**정답: C) 콘솔에서 실행 상태·디스크를 확인하고 필요하면 정확한 파일의 복구 절차 수행**

**설명:** `generate`는 검사·생성이지 연결 증명이 아닙니다. `try`는 미승인 변경을 되돌리려 하지만 공식 롤백 제한이 있습니다. 재부팅 전에 저장 설정을 확인하고, 원복할 때는 소유 파일만 옮기며 정확한 실습 주소가 실행 상태에 남았는지도 확인합니다.

</details>

6. `connection.autoconnect no`로 `beginner-lab-static`을 만들었습니다. 어떤 의미인가요?
   - A) nmcli 종료와 함께 프로필도 사라짐
   - B) 프로필은 저장됐지만 자동 활성화는 꺼짐, 명시적 활성화·검증 후 자동 연결을 켬
   - C) 이미 모든 Ethernet NIC에 활성화됨
   - D) 관리 연결만 바뀜

<details>
<summary>정답 보기</summary>

**정답: B) 프로필은 저장됐지만 자동 활성화는 꺼짐, 명시적 활성화·검증 후 자동 연결을 켬**

**설명:** 저장 설정과 장치의 활성 상태는 다릅니다. 본문은 확인한 NIC·MAC으로 대상을 제한하고 기록한 UUID를 활성화하여 주소·경로를 확인한 뒤 재부팅 자동 연결을 켭니다. 저장됐다는 사실만으로 활성화 성공은 증명되지 않습니다.

</details>

7. 이전 실습 프로필에 `DEVICE=--`가 표시됩니다. 재부팅 후 새 프로필을 사용하려면 어떻게 해야 할까요?
   - A) 모든 비활성 프로필 삭제
   - B) 비활성 프로필은 절대 활성화되지 않으므로 무시
   - C) 모든 프로필의 자동 연결 우선순위를 올림
   - D) 호환성·장치 제한과 원래 상태를 기록하고 확인된 실습 전용 경쟁 프로필만 자동 연결 해제

<details>
<summary>정답 보기</summary>

**정답: D) 호환성·장치 제한과 원래 상태를 기록하고 확인된 실습 전용 경쟁 프로필만 자동 연결 해제**

**설명:** 비활성은 현재 상태입니다. 호환되는 저장 프로필은 나중에 활성화될 수 있습니다. 장치 제한이 없는 프로필은 관리 NIC에도 쓰일 수 있으므로 무작정 바꾸지 마세요. 정확한 복원을 위해 이전 UUID·자동 연결 값·활성 상태를 보존합니다.

</details>

8. nmtui에서 `beginner-lab-static`을 편집하고 저장했습니다. 다음 행동은 무엇인가요?
   - A) nmcli로 같은 프로필을 확인하고 필요하면 기록한 실습 UUID를 재활성화
   - B) nmtui 설정을 영구화하려고 두 번째 Netplan 정의 작성
   - C) 모든 네트워크 서비스 재시작
   - D) 모든 NIC를 갱신하려고 관리 연결 비활성화

<details>
<summary>정답 보기</summary>

**정답: A) nmcli로 같은 프로필을 확인하고 필요하면 기록한 실습 UUID를 재활성화**

**설명:** nmtui와 nmcli는 같은 관리자의 인터페이스입니다. 저장과 이미 활성인 장치에 적용하는 동작은 다릅니다. 활성화 대상을 실습 전용 프로필로 한정하고 게이트웨이·DNS·기본 경로 동작을 확인하세요.

</details>

9. 본문의 기본 게이트웨이 `10.77.0.1`, resolver `10.77.0.53` 예제는 어디에 적합한가요?
   - A) 기존 NAT/DHCP 관리 NIC에 자동 개선책으로 적용
   - B) 서비스가 없어도 격리된 과정 NIC에 적용
   - C) 관리자가 해당 서비스를 확인하고 경쟁 관리 기본 경로가 없는 별도 연습 VM의 업링크에 적용
   - D) 기본 경로를 일괄 삭제한 뒤 아무 NIC에 적용

<details>
<summary>정답 보기</summary>

**정답: C) 관리자가 해당 서비스를 확인하고 경쟁 관리 기본 경로가 없는 별도 연습 VM의 업링크에 적용**

**설명:** 게이트웨이·DNS 예제에는 실제 서비스와 경로별 준비 조건이 필요합니다. DHCP 예제도 DHCP가 제공되는 망이어야 합니다. 격리 과정망에 서비스를 있다고 가정하거나 관리 연결을 바꾸라는 지시가 아닙니다. 검색 도메인은 이름을 확장하며 레코드를 생성하지 않습니다.

</details>

10. NetworkManager 실습을 취소하려 합니다. 관련 없는 설정을 보존하는 원복은 무엇인가요?
   - A) Ethernet 프로필 전체 삭제 후 재부팅
   - B) 새 실습 UUID를 확인·삭제하고 이전 프로필들의 자동 연결 값을 복원한 뒤 원래 활성 프로필만 재활성화
   - C) 모든 주소·기본 경로 일괄 삭제
   - D) 먼저 만들어진 관리 프로필 삭제

<details>
<summary>정답 보기</summary>

**정답: B) 새 실습 UUID를 확인·삭제하고 이전 프로필들의 자동 연결 값을 복원한 뒤 원래 활성 프로필만 재활성화**

**설명:** 복구에는 정확한 소유 프로필과 이전 상태 기록이 필요합니다. 원래 비활성 프로필은 비활성으로 남겨야 합니다. 연결을 내리면 다른 호환 프로필이 활성화될 수 있으므로 실습 주소·링크 상태와 관리 설정 보존을 다시 확인하세요.

</details>
