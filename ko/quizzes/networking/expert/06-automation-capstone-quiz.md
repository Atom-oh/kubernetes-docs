# 자동화와 종합 평가 퀴즈

[본문](../../../networking/expert/06-automation-capstone.md)

1. 관측 결과에 맞춰 기대값을 같은 변경에서 바꾸면 어떤 문제가 생기나요?

   - A) TCP 속도가 반드시 증가한다
   - B) 회귀나 정책 위반을 숨길 수 있다
   - C) 원본 증거가 필요 없어져 좋다
   - D) 항상 더 엄격해진다

<details>
<summary>정답 보기</summary>

**정답: B**

**설명:** 의도는 별도로 검토하고 revision/hash를 기록합니다. 관측과 기대값을 함께 임의 조정하면 검증이 자기 확인이 됩니다.

</details>

2. BGP가 Established로 돌아온 시각은 무엇을 의미하나요?

   - A) 서비스 수렴 완료와 반드시 같다
   - B) 모든 VRF 격리 성공
   - C) 제어 평면 상태이며 실제 전달·서비스 복구는 별도 측정
   - D) 모든 패킷이 손실 없이 전달됨

<details>
<summary>정답 보기</summary>

**정답: C**

**설명:** 광고, 선택, FIB, 실제 probe의 회복 시점이 다를 수 있습니다. 시간축과 관측 위치도 일치시켜야 합니다.

</details>

3. 금지 흐름의 timeout만 수집했습니다. 적절한 정규화는?

   - A) 정책 차단 근거가 없으면 unknown으로 남긴다
   - B) 항상 deny로 저장한다
   - C) 항상 allow로 저장한다
   - D) 흐름을 기록에서 삭제한다

<details>
<summary>정답 보기</summary>

**정답: A**

**설명:** timeout의 원인은 라우팅·리스너·반환 경로 등일 수 있습니다. 정책 근거와 probe가 연결돼야 정책 차단을 판단할 수 있습니다.

</details>

4. 합성 예제에서 CONSISTENT_RECORD가 출력됐습니다. 확인한 것은?

   - A) 실제 장비의 forwarding 성공
   - B) 운영 배포 승인
   - C) 실제 PCAP 원본의 진위
   - D) 입력된 의도와 기록의 필수 조건 일치

<details>
<summary>정답 보기</summary>

**정답: D**

**설명:** 검증기는 데이터 일관성을 검사합니다. synthetic 라벨이나 artifact 이름은 실제 통신·수집 사실을 증명하지 않습니다.

</details>

5. 허용한 광고는 203.0.113.0/24 하나인데 관측 집합에 0.0.0.0/0도 있습니다. 어떻게 처리하나요?

   - A) 경로가 많을수록 좋으므로 통과
   - B) 정해진 광고 범위와 달라 거절
   - C) 기대값에 자동 추가
   - D) default route는 항상 무시

<details>
<summary>정답 보기</summary>

**정답: B**

**설명:** 이 계약은 특정 peer로 광고한 정확한 prefix 집합을 비교합니다. 예상하지 않은 광고를 숨기지 않습니다.

</details>

6. artifact 참조 문자열이 있으면 어떤 검증이 남나요?

   - A) 아무것도 없다
   - B) 원본 파일은 삭제해도 된다
   - C) 존재·해시·시각·수집자·관측 지점과 실제 내용 대조
   - D) 모든 계정 권한 확대

<details>
<summary>정답 보기</summary>

**정답: C**

**설명:** 참조의 존재와 증거의 신뢰성은 다릅니다. 예제 검증기는 원본을 독립적으로 검사하지 않습니다.

</details>

7. FRR peer 광고와 Linux 전체 FIB를 같은 prefix 목록으로 비교해도 되나요?

   - A) scope가 다르므로 별도 정규화·의도와 비교해야 한다
   - B) 항상 같다
   - C) 개수가 같으면 충분하다
   - D) ECMP는 항상 하나의 경로다

<details>
<summary>정답 보기</summary>

**정답: A**

**설명:** 제어 평면 광고와 전달 상태는 다른 데이터입니다. 집합 변환에서 사라진 경로 속성이나 다중 경로도 별도로 검증합니다.

</details>

8. 복구 후 필요한 확인은?

   - A) 프로세스가 살아 있는지만 본다
   - B) 정상 흐름 하나만 성공하면 끝낸다
   - C) 점수 합계만 확인한다
   - D) 허용 흐름·격리·관리 경로를 원래 기준으로 다시 확인한다

<details>
<summary>정답 보기</summary>

**정답: D**

**설명:** 복구는 설정 복사만으로 끝나지 않습니다. 필요한 동작과 금지 조건이 함께 돌아왔는지 같은 관측 기준으로 확인합니다.

</details>
