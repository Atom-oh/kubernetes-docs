# LLM 게이트웨이(Inference Gateway) 퀴즈

제안 설계의 보장·한계를 확인합니다. 예약·캐시 의미·인가·스트리밍·PII·가드레일·문맥 라우팅을 다루며 모든 제품이 이 설계를 구현한다고 주장하지 않습니다.

## 객관식 문제

- B. 허용 시점에는 최종 사용량이 없으므로 동시 요청의 쿼터·금액을 원자적으로 예약해야 하기 때문
- C. 모든 HTTP 오류는 무료이기 때문
- D. 입력 토큰 추정이 금액 하드 캡을 보장하기 때문

<details>
<summary>정답 보기</summary>

**정답: B. 허용 시점에는 최종 사용량이 없으므로 동시 요청의 쿼터·금액을 원자적으로 예약해야 하기 때문**

**설명:**
유료 라우터·필터·guardrail·재시도도 호출별로 검사된 입력과 보수적 비용 상한을 기준으로 호출 전에 예약합니다. 본 호출 거부가 이미 발생한 보조 비용을 없애지는 않습니다. TPM 차감만으로 금액이 예약되지는 않습니다. 실제 비용으로 멱등 정산하며 중단된 스트림은 최종 사용량이 없을 수 있으므로 비용 0으로 가정하지 말고 대사까지 적절한 예약을 유지합니다.

</details>

- C. 코딩 에이전트 적중률은 항상 90%를 넘는다
- D. 교차 프로토콜 변환은 대상 캐시를 절대 예열할 수 없다

<details>
<summary>정답 보기</summary>

**정답: B. 제공자별 프롬프트·토큰 접두사와 지원 캐시 설정을 보존하며 JSON 봉투 서식만으로 재사용이 무효화되지는 않는다**

**설명:**
Anthropic은 캐시 지점까지 동일한 프롬프트 구간을, vLLM은 토큰 블록·추가 문맥의 해시를 설명합니다. 안정적인 변환은 대상에서 재사용 가능한 접두사를 만들 수 있습니다. 원문 전달보다 필수 정책 변환이 우선하며 선택 모델·TTL·워크로드의 캐시 절감 효과를 측정해야 합니다.

</details>

- C. 서킷 브레이커가 임시 권한을 부여하기 때문
- D. 비슷한 모델 이름이 동등한 기능을 증명하기 때문

**설명:**
실제 대상의 모델·리전·개인정보·필수 기능·예산을 재검사합니다. 원래 모델도 모든 검사를 통과할 때만 유지하고 아니면 거부합니다. 별칭 해석·버전 이름 정렬은 인가가 아닙니다.

</details>

- C. 최종 사용량 이벤트 이후에만

<summary>정답 보기</summary>

**설명:**
확정 이후 투명한 재시도는 내용·도구 활동을 중복시키고 추가 비용을 만들 수 있습니다. 클라이언트 프로토콜의 오류 의미로 종료하고 불완전 사용량을 기록합니다. 확정 전에도 횟수·기한 제한과 제공자 요금 계산이 필요합니다. 출력은 공개 전에 검사해야 하며 버퍼링은 사용자 TTFT를 늘릴 수 있습니다.

</details>

### 5. 개인정보 보호 요구사항과 캐시 비용은 어떻게 다뤄야 하나요?

- C. 도구 인자에는 PII가 없으므로 사용자 텍스트만 검사한다
- D. 호출자가 제공한 모든 플레이스홀더를 복원한다

<summary>정답 보기</summary>

**정답: B. 필수 개인정보 통제를 강제하고 안전할 때 범위가 제한된 안정적 변환을 사용하며 캐시·지연 영향을 측정한다**

**설명:**
민감 데이터는 텍스트뿐 아니라 도구·결과·첨부에도 있습니다. 미지원 검사는 차단하거나 승인된 대상으로 보내야 합니다. 매핑을 인증된 테넌트·주체·세션에 결합하고 복원을 인가해야 하며 매핑 손실은 정확성에도 영향을 줍니다. 탐지에는 누락이 있으므로 게이트웨이·분류기 모두 유출 0을 증명하지 못합니다.

</details>

- C. 민감 정보 마스킹을 보장하려면 비동기 모드를 사용한다
- D. 모든 Bedrock API에서 같은 최상위 JSON 필드를 사용한다

<details>
<summary>정답 보기</summary>

**정답: B. 선택 API의 가드레일 필드를 사용하고 범위를 확인하며 지원되는 곳에서 승인 ID·버전을 강제한다**

**설명:**
Converse는 guardrailConfig, InvokeModel은 guardrailIdentifier·guardrailVersion 작업 파라미터(HTTP 헤더)를 사용합니다. guardContent는 평가 범위를 정할 수 있고 ApplyGuardrail은 모델 호출 없이 별도 평가합니다. 적절한 IAM 조건·우회 방지가 정책을 강화합니다. 비동기 스트리밍은 검사 전에 내용을 공개할 수 있고 민감 정보 마스킹을 지원하지 않으며 로그·추적도 보호해야 합니다.

</details>

### 7. 캐시 지점 근처에 게이트웨이 정책 프롬프트를 삽입할 때 중요한 것은 무엇인가요?

- C. 캐시 표식 뒤의 블록은 앞 구간을 항상 무효화한다

<details>
<summary>정답 보기</summary>

**설명:**
캐시 재사용은 동일한 지원 구간·모델 조건·최소 길이·범위·TTL에 따릅니다. 뒤 블록은 앞선 캐시 구간을 반드시 무효화하는 것이 아니라 그 밖에 있습니다. 복사한 정책 표식으로 필수 삽입·검사를 생략해서는 안 됩니다. 프롬프트는 안내이지 실행 인가가 아닙니다.

</details>

### 9. 보수적인 분산 금액 예산을 뒷받침하는 불변식은 무엇인가요?

- C. 할당 합계가 자동으로 최악의 초과 지출 한계가 된다
- D. 만료된 할당은 항상 즉시 재발급해도 된다

<details>
<summary>정답 보기</summary>

**설명:**
가용 예산에서 뺀 할당은 초과 허용액이 아니라 예약 용량입니다. 보수적 비용 상한·원자적 로컬 허용·영속 ID·대사를 사용합니다. 만료는 새 요청만 막으며 미해결 작업·보고가 있으면 안전하게 회수할 수 없습니다. 유료 보조·본 모델·출력 검사 호출은 각각 예약을 거쳐 같은 예산을 사용합니다. 금액 리스가 레이트 카운터까지 자동 전역화하지는 않습니다.

</details>

- C. 소스 엔드포인트 리전이 모든 처리 위치를 증명한다

**설명:**
