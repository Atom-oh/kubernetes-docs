# 可观测性实验 03 测验

<span id="observability-lab-part-3-msa-deployment-and-canary-quiz"></span>

> **最后更新**：2026 年 9 月 13 日

1. 订单/outbox 的事务边界是什么？
   - A) 提交订单，然后忽略失败的消息传递。
   - B) 在一个数据库事务中同时提交或回滚。
   - C) SNS 和数据库会自动保持原子性。
   - D) 为每个请求初始化数据库。

<details>
<summary>显示答案</summary>

**答案：B) 在一个数据库事务中同时提交或回滚。**

验证数据库回滚以及未发布 outbox 记录的保留。

</details>

---

2. 谁拥有支付工作负载？
   - A) Deployment 和 Rollout 同时拥有。
   - B) 单个 Rollout。
   - C) KEDA 和 Rollout 争夺副本数的控制权。
   - D) Grafana。

<details>
<summary>显示答案</summary>

**答案：B) 单个 Rollout。**

明确控制器所有权和 Git 期望状态。

</details>

---

3. 为什么要分离通知队列与分析队列？
   - A) 在同一个队列上竞争消费就是扇出。
   - B) 这样每个消费者都能独立接收同一个事件。
   - C) SQS 仅支持一个队列。
   - D) 这可以消除所有重复。

<details>
<summary>显示答案</summary>

**答案：B) 这样每个消费者都能独立接收同一个事件。**

SNS 扇出和各消费者按事件 ID 去重是不同的职责。

</details>

---

4. 对完全相同的重复模拟支付请求会发生什么？
   - A) 始终创建新的支付记录。
   - B) 复用已存储的结果；冲突的值返回 409。
   - C) 对真实卡收费。
   - D) 即使没有订单也始终成功。

<details>
<summary>显示答案</summary>

**答案：B) 复用已存储的结果；冲突的值返回 409。**

该实验未实现真实的支付网关。

</details>

---

5. 如果在 SNS 发布之后、数据库标记之前发生崩溃，会怎样？
   - A) 自动实现恰好一次语义。
   - B) 可能会重新投递，因此消费者需要去重。
   - C) 删除所有 outbox 行。
   - D) 始终确认消息。

<details>
<summary>显示答案</summary>

**答案：B) 可能会重新投递，因此消费者需要去重。**

外部副作用需要额外的幂等性约定。

</details>

---

6. 哪个工作负载会随 SQS 队列积压量扩缩容？
   - A) 始终只有 API 生产者。
   - B) 该队列的消费者。
   - C) 数据库管理员。
   - D) NLB。

<details>
<summary>显示答案</summary>

**答案：B) 该队列的消费者。**

KEDA 读取队列属性；它不消费消息。

</details>

---

7. 金丝雀成功率查询应选择什么？
   - A) 所有稳定版本和金丝雀流量。
   - B) 仅新的 Pod 模板修订版本。
   - C) 每个命名空间。
   - D) 仅部署前的平均值。

<details>
<summary>显示答案</summary>

**答案：B) 仅新的 Pod 模板修订版本。**

不要让大量稳定版本流量掩盖失败的金丝雀版本。

</details>

---

8. 应如何处理空/NaN/Inf 结果？
   - A) 始终为 100% 成功。
   - B) 不通过成功条件。
   - C) 将所有结果转换为零并通过。
   - D) 指标并非必需。

<details>
<summary>显示答案</summary>

**答案：B) 不通过成功条件。**

同时检查最低请求数量和可观测性。

</details>

---

9. 指标中应包含哪些标签？
   - A) 每个订单 ID。
   - B) 服务、基数有界的路由、状态和修订版本。
   - C) 客户/银行卡数据。
   - D) 完整的请求体。

<details>
<summary>显示答案</summary>

**答案：B) 服务、基数有界的路由、状态和修订版本。**

唯一 ID 会带来基数/隐私问题；请适当使用追踪/日志关联。

</details>

---

10. Rollout 中止意味着什么？
   - A) Git 会自动还原。
   - B) 它与 Git 回退或期望镜像的恢复相互独立；请显式恢复权威来源中的状态。
   - C) 所有数据库写入都会回滚。
   - D) 新镜像会被永久删除。

<details>
<summary>显示答案</summary>

**答案：B) 它与 Git 回退或期望镜像的恢复相互独立；请显式恢复权威来源中的状态。**

不要同时让直接执行的 Helm 和 ArgoCD 管理同一资源。

</details>
