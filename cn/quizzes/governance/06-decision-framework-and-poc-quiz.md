# 决策框架与 PoC 设计测验

> 本测验用于检查你对[决策框架与 PoC 设计](../../governance/06-decision-framework-and-poc.md)的理解。

---

1. 本文档指出，在各项决策因素中“最大的缺口”是什么？
   - A) 标签命名约定
   - B) CUJ 级别的 RTO/RPO 目标
   - C) EKS 版本号
   - D) VPC CIDR 大小

<details>
<summary>显示答案</summary>

**答案：B) CUJ 级别的 RTO/RPO 目标**

**说明：**
如果没有按 CUJ 定义 RTO/RPO 目标，就无法判断 A/B EKS Runtime 故障转移是否足够快、哪种数据所有权模式实际可恢复，或 AZ 配置差异是否重要。应先定义此目标，再进行其他工作。

</details>

---

2. ALB 加权转发与 fail-open 有何关系？
   - A) 不健康的组总会故障转移到另一组
   - B) 组间自动故障转移与组内对不健康目标的路由是两个不同机制
   - C) 权重可以保证 RTO
   - D) 目标会在不同 Region 之间复制

<details>
<summary>显示答案</summary>

**答案：B) 组间自动故障转移与组内对不健康目标的路由是两个不同机制**

**说明：**
加权转发不会自动将空组/不健康组的权重转移到另一组。应单独评估所选组的 DNS/路由健康阈值。

</details>

---

3. 为什么要在其他所有 PoC 之前将“决策矩阵试运行”作为 PoC-0？
   - A) 因为它是最便宜的选项
   - B) 因为其他每个选项（独立边界判断、Hybrid 配置等）都把“可通过决策矩阵复现”作为有效条件，所以没有决策矩阵就不能把任何 PoC 结果转化为标准
   - C) 因为它需要 AWS SA 批准
   - D) 因为它与其他 PoC 无关

<details>
<summary>显示答案</summary>

**答案：B) 因为其他每个选项（独立边界判断、Hybrid 配置等）都把“可通过决策矩阵复现”作为有效条件，所以没有决策矩阵就不能把任何 PoC 结果转化为标准**

**说明：**
决策矩阵试运行由两人分别对 10–15 个有代表性的工作负载应用该矩阵，本设计采用的示例目标为分歧率低于 20%、例外率低于 15%。所得 Account/VPC/集群数量估算用于确定剩余 PoC 的测量目标。

</details>

---

4. 哪项说法正确描述了未使用 Region 的控制？
   - A) 可以禁用每个默认启用的 Region
   - B) 结合 SCP、检测、受支持的选择加入型 Region 禁用方式，以及对现有资源成本的检查
   - C) 仅靠 GuardDuty 就能阻止 API 调用
   - D) 禁用 Region 会删除其中所有资源

<details>
<summary>显示答案</summary>

**答案：B) 结合 SCP、检测、受支持的选择加入型 Region 禁用方式，以及对现有资源成本的检查**

**说明：**
默认启用的 Region 无法禁用。禁用选择加入型 Region 不会删除现有资源，也不能确保费用停止，因此应一并规划清理和访问控制。

</details>
