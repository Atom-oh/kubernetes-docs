# Amazon Managed Blockchain 测验

本测验检查你对 AMB 组件、受管/自运营边界和服务终止风险的理解。

## 选择题

1. 应如何比较 AMB 提供的各项服务？
   - A) 三项服务解决相同问题，只是价格不同
   - B) 区分 Fabric/专用节点、无服务器 Access 和 Query API，并关注各自的计费方式和功能
   - C) 它们分别面向开发、暂存和生产环境
   - D) 它们分别面向公有链、私有链和混合链

<details>

<summary>显示答案</summary>

**答案**：B) 区分 Fabric/专用节点、无服务器 Access 和 Query API，并关注各自的计费方式和功能

**说明**：AMB 并非一概按节点计费。专用资源、无服务器 RPC 请求和索引化 Query API 采用不同的定价和覆盖范围。
</details>

2. AMB 受管节点无法解决的最重要问题是什么？
   - A) CloudWatch 指标收集
   - B) 验证者运维：受管节点用于查询和提交；PoS 质押还需要另一套密钥管理、签名可用性和罚没风险管理要求
   - C) 基于 IAM 的访问控制
   - D) VPC 私有连接

<details>

<summary>显示答案</summary>

**答案**：B) 验证者运维：受管节点用于查询和提交；PoS 质押还需要另一套密钥管理、签名可用性和罚没风险管理要求

**说明**：AMB Access 公有链节点用于读取链上数据和提交交易。PoS 验证还需要满足签名可用性和防止罚没的要求。协调不当的签名器可能为同一个验证者生成互相冲突、会导致罚没的消息；相同的重复签名则不会自动导致罚没。常规部署使用单个活动签名器，配合有隔离保护的故障切换，并保留罚没历史；分布式签名器需要经过验证的协调机制。AMB 节点访问不会提供这种验证者设计，因此质押仍需单独运维或使用专门服务。
</details>

3. 受管与自运营的决策中，哪项是步骤 1？
   - A) 成本是多少？
   - B) 你是否真的需要节点？如果只查询数据，AMB Query 或第三方 RPC 可能已经足够
   - C) 你要使用哪条链？
   - D) 你有多少运维人员？

<details>

<summary>显示答案</summary>

**答案**：B) 你是否真的需要节点？如果只查询数据，AMB Query 或第三方 RPC 可能已经足够

**说明**：决策顺序是：① 是否真的需要节点 → ② 是否需要控制权 → ③ 成本 → ④ 是否可以混用。运行节点成本高、负担重，因此必须先确认确有需要，**许多情况在步骤 1 就会被排除**。在步骤 2 中，如果需要自行选择客户端、调优、归档或参与验证，就意味着需要自运营。
</details>

4. Amazon QLDB 案例对架构决策有什么启示？
   - A) 受管服务总比自运营便宜
   - B) 受管服务也可能停止提供；其迁移路径未必在功能上等价：迁移到 Aurora PostgreSQL 会失去密码学可验证性
   - C) 账本数据库只能通过区块链实现
   - D) AWS 服务在正式发布后至少保证支持五年

<details>

<summary>显示答案</summary>

**答案**：B) 受管服务也可能停止提供；其迁移路径未必在功能上等价：迁移到 Aurora PostgreSQL 会失去密码学可验证性

**说明**：QLDB 于 2018 年公布，2019 年正式发布，AWS 于 2024 年 7 月宣布结束支持，并且**该服务已于 2025 年 7 月 31 日结束**。AWS 提供的迁移方案是 Aurora PostgreSQL；虽然可以通过扩展实现类似账本的功能，但这并不能替代 QLDB 的核心价值——“从数学上证明数据未被篡改”。可吸取的教训包括：① 受管服务存在停止服务的风险；② “有替代品”不等于“功能相同”；③ 通知期可能很短；④ 使用标准技术更容易迁出。
</details>

5. 缓解服务停止风险最有效的措施是什么？
   - A) 同时部署到多个云服务商
   - B) 使用标准协议和抽象层：让应用程序通过标准 RPC 接口通信，从而可在 AMB、自运营节点和第三方服务之间替换后端
   - C) 不使用受管服务
   - D) 与 AWS 签订长期合同

<details>

<summary>显示答案</summary>

**答案**：B) 使用标准协议和抽象层：让应用程序通过标准 RPC 接口通信，从而可在 AMB、自运营节点和第三方服务之间替换后端

**说明**：Ethereum JSON-RPC 等标准接口可以简化兼容后端之间的替换，而 AMB 专有 API 会带来耦合。应独立保留必需数据，并测量重新同步/迁移所需时间。使用服务前就应规划密钥恢复和退出方案：**KMS 私有签名密钥无法导出**。应区分公钥下载、已导入密钥材料的备份、CloudHSM 的可导出性/包装规则，以及账户/合约轮换选项；选择受管密钥本身并不能提供可移植的私钥备份。
</details>

6. 为什么 AMB 的 IAM 集成是一项实质性优势？
   - A) IAM 会替你签署区块链交易
   - B) 自运营节点的 RPC 端点需要自行实现身份验证方案或仅依赖网络层控制；AMB 则可通过 IAM 控制，并与内部权限模型保持一致
   - C) IAM 会自动备份密钥
   - D) IAM 策略可以修改链上数据

<details>

<summary>显示答案</summary>

**答案**：B) 自运营节点的 RPC 端点需要自行实现身份验证方案或仅依赖网络层控制；AMB 则可通过 IAM 控制，并与内部权限模型保持一致

**说明**：自行运营节点的 RPC 端点时，必须构建身份验证机制，或仅依赖安全组、NetworkPolicy 等网络层控制。AMB 可以使用 IAM 策略控制，并与内部权限模型一致管理。还可以集成 CloudWatch 指标/日志、CloudTrail 管理 API 审计、VPC Endpoint/PrivateLink 私有连接，以及 KMS 密钥管理。
</details>

7. AMB 文档中哪项标记为 `Needs verification`？
   - A) AMB Query 通过 API 提供数据
   - B) AMB 支持的链列表、区域可用性以及 Preview/GA 状态
   - C) QLDB 已于 2025 年 7 月 31 日结束服务
   - D) AMB 支持 Hyperledger Fabric

<details>

<summary>显示答案</summary>

**答案**：B) AMB 支持的链列表、区域可用性以及 Preview/GA 状态

**说明**：支持的链和服务状态会随时间变化。已确认的变更包括：Ethereum Goerli 测试网于 2024 年 4 月 1 日结束，Polygon Mumbai 测试网于 2024 年 4 月 15 日结束；Polygon PoS 主网也曾处于 Public Preview 阶段。

AMB 的停止服务时间已不再是待确认事项：AWS 将于 2026 年 10 月 29 日停止接纳新的 AMB 客户，并于 2027 年 9 月 29 日终止访问（AMB 迁移指南，https://docs.aws.amazon.com/managed-blockchain/latest/ethereum-dev/migrating-node-rpc-workloads.html）。
</details>
